# Lab packs — data notes

Each `.json` file here is an exercise with a `lab` block (v1.4 spec
§6.2, v1.4b spec §7.1): handout, settings table, the "what the tool
shows you vs what NeoPhylo shows you" note, and the chain it
reproduces — PHYLIP programs for the schema-3 packs (`tool` absent)
and MEGA menu runs for the schema-4 MEGA handouts (`tool: "mega"`).
Expected numbers are checked against the committed PHYLIP and MEGA-CC
fixtures in `web/src/labs/packs.test.ts`; the PHYLIP menu options and
defaults in each settings table were read off the installed PHYLIP
3.697 menus, and the MEGA settings rows cite the committed
`fixtures/mega/mao/*.mao` analysis files verbatim.

## `dnadist-neighbor` dataset

- **File:** `fixtures/inputs/k80_10.fasta`, embedded verbatim in the
  pack's `data.fasta` (the test compares records byte for byte).
- **Shape:** 10 taxa (`t01`–`t10`) × 800 aligned sites, no gaps.
- **Provenance:** simulated in-house by this repository's fixture
  generators under K80 with κ = 6, so transitions dominate and the F84
  correction matters (`fixtures/README.md`, inputs section). Original
  data, no third-party source.
- **License:** the repository's license — AGPL-3.0-only (`LICENSE`); no
  entry in `THIRD_PARTY_NOTICES.md` is needed because nothing here is
  redistributed third-party material.
- **Expected numbers:** `fixtures/phylip/f84/k80_10.json` — dnadist's
  printed F84 matrix (`distances.F84`, 6 decimals) and `neighbor`'s NJ
  tree on that printed matrix (`nj.F84`, 5-decimal branch lengths),
  generated by `fixtures/generate_phylip.sh` with PHYLIP 3.697.

## `protdist-neighbor` dataset

- **File:** `fixtures/inputs/protein/p10_400.fasta`, embedded verbatim
  in the pack's `data.fasta` (the test compares records byte for byte).
- **Shape:** 10 sequences (`P01`–`P10`) × 400 aligned sites, standard
  amino acids only, no gaps or ambiguity codes.
- **Provenance:** simulated in-house by `fixtures/make_protein_inputs.py`
  (numpy PCG64, seed 2026): sequences evolved down a random binary
  tree, branch lengths uniform in [0.05, 0.4], under equal-rate
  replacement among the 20 standard amino acids (`fixtures/README.md`,
  inputs/protein section). The data was NOT simulated under JTT — JTT
  is protdist's default correction, not the generator's model.
  Original data, no third-party source.
- **License:** the repository's license — AGPL-3.0-only (`LICENSE`); no
  entry in `THIRD_PARTY_NOTICES.md` is needed because nothing here is
  redistributed third-party material.
- **Expected numbers:** `fixtures/ref/protein/p10_400.json` —
  protdist's printed JTT matrix (`distances.JTT` — protdist prints 6
  decimals; the file's `precision` field records 4, the smallest
  decimal count surviving the JSON round-trip, so tests compare within
  `0.5·10^-precision`) and `neighbor`'s NJ tree on that printed matrix
  (`nj.JTT`, 5-decimal branch lengths including P05's negative edge),
  generated by `fixtures/generate_phylip.sh` with PHYLIP 3.697.

- **Provenance:** simulated in-house by this repository's fixture

- **License:** the repository's license — AGPL-3.0-only (`LICENSE`); no

  redistributed third-party material.
- **Expected numbers:** `fixtures/phylip/chain/jc12_boot100.json` —

## `mega-jc69-vs-k2p` dataset

- **File:** `web/public/library/primate-mtdna.fasta`, embedded verbatim
  in the pack's `data.fasta` (the test compares records byte for byte).
- **Shape:** 7 taxa × 1,138 aligned sites — the mitochondrial control
  region (D-loop) of the hominoid accessions Horai et al. (1995)
  published: human, chimpanzee, bonobo, gorilla, two orangutans and
  gibbon. Same public records as MEGA's own example data; this is the
  D-loop subset, not that file's whole mtDNA alignment — the handout
  says so explicitly.
- **Provenance:** `web/public/library/primate-mtdna.json` — NCBI
  Nucleotide accessions D38112, D38113, D38116, D38114, D38115,
  X97707, X99256, aligned with MAFFT 7.525 `--auto` by
  `scripts/data/build_library.py`.
- **License:** NCBI data policy — no NCBI restrictions on use or
  distribution; submitters may claim rights (recorded in
  `THIRD_PARTY_NOTICES.md`).
- **Gap treatment:** the lab's runs use pairwise deletion — MEGA's own
  default and the treatment the cited `.mao` files declare.
- **Expected numbers:** `fixtures/mega/library/primate-mtdna.json` —
  MEGA-CC 12.1.4's printed `JC69/pairwise` and `K80/pairwise` distance
  matrices (8 decimals) and its `nj/JC69/pairwise` and
  `nj/K80/pairwise` Newicks, generated by `fixtures/generate_mega.sh`
  against the `.mao` files the settings table cites
  (`dist_dna_jc69_pairwise.mao`, `dist_dna_k2p_pairwise.mao`,
  `nj_dna_jc69_pairwise.mao`, `nj_dna_k2p_pairwise.mao`). Every MEGA
  setting a settings row names is checked against the `.mao` files
  verbatim — the table cannot drift from the runs it cites.
- **Cross-check route:** the handout tells the student to export the
  alignment as `.meg` from NeoPhylo and open that file in MEGA with
  the table's settings — the fixtures pin those numbers.

## `mega-nj-vs-upgma` dataset

- **File:** `web/public/library/globins.fasta`, embedded verbatim in
  the pack's `data.fasta` (the test compares records byte for byte).
- **Shape:** 23 taxa × 156 aligned amino-acid sites — vertebrate
  alpha, beta and gamma globins plus human myoglobin.
- **Provenance:** `web/public/library/globins.json` — UniProtKB
  records (one accession per sequence), aligned with MAFFT 7.525
  `--auto` by `scripts/data/build_library.py`.
- **License:** CC BY 4.0 (UniProtKB), recorded in
  `THIRD_PARTY_NOTICES.md`.
- **Gap treatment:** the lab's runs use pairwise deletion — MEGA's own
  default and the treatment the cited `.mao` files declare.
- **Model:** Poisson, not JTT — MEGA's own JTT estimator differs from
  the JTT NeoPhylo ships (`fixtures/worked/mega-notes.md` "JTT
  verdict", #117), so the handout's runs use the protein model that
  reproduces MEGA exactly.
- **Expected numbers:** `fixtures/mega/library/globins.json` —
  MEGA-CC 12.1.4's printed `Poisson/pairwise` distance matrix (8
  decimals) and its `nj/Poisson/pairwise` and `upgma/Poisson/pairwise`
  Newicks, generated by `fixtures/generate_mega.sh` against the `.mao`
  files the settings table cites (`dist_protein_poisson_pairwise.mao`,
  `nj_protein_poisson_pairwise.mao`,
  `upgma_protein_poisson_pairwise.mao`). Every MEGA setting a settings
  row names is checked against the `.mao` files verbatim.
- **The UPGMA tie:** `Human_HBA`, `Horse_HBA` and `Cow_HBA` are an
  exact three-way tie under pairwise deletion (a two-way tie under
  complete/partial95 — `fixtures/worked/mega-notes.md` "Ties in
  globins"). MEGA's UPGMA tree and NeoPhylo's may resolve the tie
  differently; both are valid UPGMA trees. The packs test compares
  UPGMA tie-aware — the exact comparison first, then a replay of
  MEGA's tree on the engine's matrix that must pass through a step
  with more than one minimal pair (the same rule
  `crates/neophylo-core/tests/parity_mega_library.rs` uses).
- **Cross-check route:** same as handout 1 — export `.meg` from
  NeoPhylo, open in MEGA, apply the table's settings.

## `mega-bootstrap-100` dataset

- **File:** `web/public/library/16s-rrna.fasta`, embedded verbatim in
  the pack's `data.fasta` (the test compares records byte for byte).
- **Shape:** 27 bacterial 16S ribosomal RNA sequences — one genus each
  — × 1,628 aligned sites, with real indels: complete deletion keeps
  1,199 columns, pairwise keeps all 1,628 available to each pair.
- **Provenance:** `web/public/library/16s-rrna.json` — NCBI RefSeq
  ribosomal-RNA records (one NR_* accession per sequence), aligned
  with MAFFT 7.525 `--auto` by `scripts/data/build_library.py`.
- **License:** NCBI data policy — no NCBI restrictions on use or
  distribution; submitters may claim rights (recorded in
  `THIRD_PARTY_NOTICES.md`).
- **Gap treatments:** the handout's two runs are pairwise deletion
  (MEGA's default, the treatment the lab loads) then complete deletion
  — the two values the cited `.mao` files declare.
- **Expected numbers:** `fixtures/mega/library/16s-rrna.json` —
  MEGA-CC 12.1.4's printed `K80/pairwise` and `K80/complete` distance
  matrices (8 decimals), its `nj/K80/{pairwise,complete}` Newicks and
  its `bootstrap["nj/K80/{pairwise,complete}"]` 100-replicate blocks,
  generated by `fixtures/generate_mega.sh` against the `.mao` files
  the settings table cites (`njboot_dna_k2p_pairwise.mao`,
  `njboot_dna_k2p_complete.mao`). Every MEGA setting a settings row
  names is checked against the `.mao` files verbatim — the one
  exception is the seed row, which carries no `.mao` key because
  MEGA's bootstrap is unseeded (`fixtures/worked/mega-notes.md` "No
  seed option") and says so.
- **Bootstrap support is compared by split set only** (owner ruling
  on #126, `docs/decisions.md` "v1.4b Task 9 Step 3"): the engine's NJ
  splits under each filter must equal the 100-replicate block's
  labelled splits and the fixture tree's splits; the 100-replicate
  support numbers themselves are never compared to NeoPhylo's (parity
  on support lives at 1,000 replicates in
  `crates/neophylo-core/tests/parity_mega_library.rs`). On this data
  both recorded runs label the same split set — the same tree under
  both gap treatments — while several supports differ by 20+ points;
  the packs test pins that premise off the fixture.
- **Cross-check route:** same as handout 1 — export `.meg` from
  NeoPhylo, open in MEGA, apply the table's settings; the exported
  `.meg` opened in MEGA gives the fixture's numbers.

## `mega-interpreting-support` dataset

- **File:** `web/public/library/16s-rrna.fasta`, embedded verbatim in
  the pack's `data.fasta` (the test compares records byte for byte) —
  the same alignment as `mega-bootstrap-100`.
- **Second dataset:** `web/public/samples/weak-support.fasta` — six
  sequences `A`–`F` × 120 DNA sites, simulated in-house by
  `scripts/samples/weak_support.py` (seed 5) so that at least one
  grouping draws weak support. It is used for a NeoPhylo-only part of
  the handout (owner decision 2026-11-04): there is no MEGA fixture
  for it, so the handout never states a value for it and asks
  questions only.
- **Provenance:** `web/public/library/16s-rrna.json` — NCBI RefSeq
  ribosomal-RNA records (one NR_* accession per sequence), aligned
  with MAFFT 7.525 `--auto` by `scripts/data/build_library.py`. The
  weak-support sample is original in-house data with no third-party
  source (`scripts/samples/weak_support.py`).
- **License:** NCBI data policy for the 16S records — no NCBI
  restrictions on use or distribution; submitters may claim rights
  (recorded in `THIRD_PARTY_NOTICES.md`). The sample carries the
  repository's license — AGPL-3.0-only (`LICENSE`).
- **Gap treatment:** pairwise deletion for the whole lab — the
  treatment the lab loads and both cited `.mao` files declare
  (`njboot_dna_k2p_pairwise.mao`,
  `njboot1000_dna_k2p_pairwise.mao`).
- **Expected numbers:** `fixtures/mega/library/16s-rrna.json` —
  MEGA-CC 12.1.4's printed `K80/pairwise` distance matrix (8
  decimals), its `nj/K80/pairwise` Newick and its
  `bootstrap["nj/K80/pairwise"]` 100-replicate block — plus
  `fixtures/mega/library/boot1000/16s-rrna.json`'s
  `bootstrap["nj/K80/pairwise"]` 1,000-replicate block, generated by
  `fixtures/generate_mega.sh` against the two `.mao` files the
  settings table cites. Every MEGA setting a settings row names is
  checked against the `.mao` files verbatim — the one exception is
  the seed row, which carries no `.mao` key because MEGA's bootstrap
  is unseeded (`fixtures/worked/mega-notes.md` "No seed option") and
  says so.
- **Support is compared by split set only** (owner ruling on #126,
  `docs/decisions.md` "v1.4b Task 9 Step 3"): the packs test pins
  that the engine's NJ splits equal the 100-replicate block's
  labelled splits, the 1,000-replicate block's labelled splits and
  the fixture tree's splits — the handout's "same groupings at both
  counts" claim. The under-50 premise is fixture-only too: the same
  two splits sit under 50 in both recorded blocks and are both
  blocks' two weakest, while a third split sits just over 50 in
  both. The seeded NeoPhylo run's own under-50 set (the fixture's
  two plus that borderline split) is engine-internal — no NeoPhylo
  support number is ever compared to a MEGA one.
- **Cross-check route:** same as handout 3 — export `.meg` from
  NeoPhylo, open in MEGA, apply the table's settings at 100
  replicates, then at 1,000.
