# fixtures/ — reference oracle

Reference outputs that the engine's corpus test (`tests/corpus.rs`) and the
worked-example tests replay. **Regenerate only through the scripts below**;
see `AGENTS.md` for the rules.

## Layout

- `inputs/*.fasta` — five committed alignments: 6–12 taxa, 200–2,000 sites.
  `jc8_gaps.fasta` carries `-` gaps and `N`s; `k80_10.fasta` was simulated
  under K80 with κ = 6 so transitions dominate. None has a tied minimum at
  any join (the generator asserts this and fails if one appears).
- `inputs/protein/*.fasta` — four committed protein alignments (6–12 taxa,
  100–400 sites, standard amino acids only, `P01`-style names), generated
  by `make_protein_inputs.py` (numpy, seed 2026): sequences evolved down a
  random binary tree, branch lengths in [0.05, 0.4], equal-rate
  replacement among the 20 standard amino acids. Committed, not
  regenerated by the CI fixture job.
- `ref/<name>.json` — ape/phangorn output, full precision (`precision: null`).
- `ref/<name>_phylip.json` — PHYLIP 3.697 output for `jc6` and `k80_10`;
  `precision` is the number of printed decimals, so compare within
  `0.5·10^-precision`. PHYLIP has no p-distance, so `distances` has only
  `JC69` and `K80`.
- `ref/protein_<name>.json` — PHYLIP `protdist` output for
  `inputs/protein/<name>.fasta`: `distances.JTT` (protdist default) and
  `distances.Kimura`, plus `nj.JTT` from `neighbor`. Saturated Kimura
  cells appear as `-1`, protdist's saturation marker. `second_opinion`
  holds `phangorn::dist.ml(model = "JTT")` and `ape::dist.aa(pairwise.
deletion = TRUE, scaled = TRUE)` at full precision — a cross-check, not
  a gate (JTT implementations differ measurably).
- `worked/*.json` — hand-entered textbook step traces (see below).
- `worked/protdist_doc_jtt.json` — the 5-sequence test data from PHYLIP's
  `protdist` documentation read as protein, with the published JTT matrix
  (6 decimals). `{"labels", "sequences", "alphabet": "protein", "jtt"}`.

## ref/ JSON format

```json
{ "name": "...", "generator": "ape <v> / phangorn <v> | phylip <v>",
  "labels": ["..."], "input": "inputs/x.fasta",
  "distances": { "raw": [[...]], "JC69": [[...]], "K80": [[...]] },
  "nj": { "JC69": "<newick>", "K80": "<newick>" },
  "upgma": { "JC69": "<newick>" },
  "precision": null }
```

`distances` entries are dense n×n row-major arrays of numbers.

## worked/ JSON format

Per-step textbook traces, same field names as `NjStep`/`UpgmaStep`
(spec §4.5). Conventions:

- `matrix`/`distance`/`q` are `{"n": n, "data": [...]}` — `Matrix` row-major.
- `active`/`new_node`/`a`/`b`/`c` hold `NodeId` numbers; `chosen` is the pair
  of **positions** in `active`, `i < j`, lexicographically smallest on ties.
- Actives keep remaining taxa in input order with the new node appended.
- `q`'s diagonal is `0` (unused by the algorithm).
- `new_row` lists distances from the new node to the remaining actives, in
  their `active` order.
- NJ files end with `final_join` (`a`, `b`, `c` are the last three actives in
  order). `step` numbers are 1-based join numbers.

## Regenerating

```sh
python3 fixtures/make_protein_inputs.py  # regenerate inputs/protein/*.fasta
bash fixtures/generate_phylip.sh         # dnadist/protdist + neighbor -> ref/*_phylip.json, ref/protein_*.json
Rscript fixtures/generate.R              # ape/phangorn fixtures -> ref/*.json; second_opinion -> ref/protein_*.json
```

Order matters: `generate_phylip.sh` must run **before** `generate.R`, which
reads `ref/protein_*.json` back for its protdist-JTT tie check and merges
`second_opinion` into the same files. `scripts/ci/fixture-guard.sh` holds
that order; `FIXTURES=1 ./scripts/check.sh` runs both and fails if the
outputs drift from what is committed.

## Tool versions used

ape 5.8.1, phangorn 2.12.1, jsonlite 2.0.0 on R 4.5.2; PHYLIP 3.697
(`dnadist` JC69 via `D D`, Kimura 2-parameter via `D`; `protdist` JTT by
default, Kimura after 3 `P` toggles — the count is read off the menu each
run; `neighbor` NJ default, `N` toggles UPGMA).
