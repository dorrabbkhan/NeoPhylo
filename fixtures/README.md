# fixtures/ — reference oracle

Reference outputs that the engine's corpus test (`tests/corpus.rs`) and the
worked-example tests replay. **Regenerate only through the scripts below**;
see `AGENTS.md` for the rules.

## Layout

- `inputs/*.fasta` — five committed alignments: 6–12 taxa, 200–2,000 sites.
  `jc8_gaps.fasta` carries `-` gaps and `N`s; `k80_10.fasta` was simulated
  under K80 with κ = 6 so transitions dominate. None has a tied minimum at
  any join (the generator asserts this and fails if one appears).
- `inputs/protein/*.fasta` — four committed protein alignments (6–12 taxa,
  100–400 sites, standard amino acids only, `P01`-style names), generated
  by `make_protein_inputs.py` (numpy, seed 2026): sequences evolved down a
  random binary tree, branch lengths in [0.05, 0.4], equal-rate
  replacement among the 20 standard amino acids. Committed, not
  regenerated by the CI fixture job.
- `ref/<name>.json` — ape/phangorn output, full precision (`precision: null`).
- `ref/<name>_phylip.json` — PHYLIP 3.697 output for `jc6` and `k80_10`;
  `precision` is the number of printed decimals, so compare within
  `0.5·10^-precision`. PHYLIP has no p-distance, so `distances` has only
  `JC69` and `K80`.
- `ref/protein/<name>.json` — PHYLIP `protdist` output for
  `inputs/protein/<name>.fasta`: `distances.JTT` (protdist default) and
  `distances.Kimura`, plus `nj.JTT` from `neighbor`. They live in a
  subdirectory so the corpus test's flat `ref/*.json` glob keeps seeing
  only DNA fixtures until the engine learns protein (Task 6 globs
  `ref/protein/`). Saturated Kimura cells appear as `-1`, protdist's
  saturation marker. `second_opinion` holds `phangorn::dist.ml(model =
"JTT")` and `ape::dist.aa(pairwise.deletion = TRUE, scaled = TRUE)`
  rounded to 8 decimals (dist.ml is an iterative optimizer; the last
  ~1e-14 differs between BLAS/R builds) — a cross-check, not a gate.
- `phylip/f84/<name>.json` and `phylip/k2p/<name>.json` — PHYLIP
  `dnadist` F84 (its default model, T = 2.0, empirical frequencies) and
  "Kimura 2-parameter" at T = 2.0 and 4.0, on every gap-free input
  (`jc6`, `jc7_long`, `jc12`, `k80_10`). Same shape as `ref/*_phylip.json`
  (f84 has no `upgma`, k2p has no trees); `model` names the `DistModel`
  replayed and the k2p `distances` keys are the ratio handed to
  `K2pPhylip { ratio }`. Each f84 file's `nj.F84` is `neighbor`'s
  unrooted NJ tree on dnadist's printed F84 matrix — the lab pack 1
  chain (v1.4 spec §3.2); `neighbor` reports the same 3.697 recorded in
  `generator` (the script asserts this). Compare trees as unrooted
  topologies, then branch lengths within half an ulp of `neighbor`'s
  printed precision (5 decimals). `precision` is dnadist's printed
  precision (6 decimals, `output_matrix_d` `%*.6f`), so compare
  distances within `0.5e-6`. They live in their own directory because
  the corpus test flat-globs `ref/*.json`; `tests/parity_phylip_v14.rs`
  owns them. A `-1.000000` cell is dnadist's inestimable marker
  (`Cell::Saturated` in the engine).
- `worked/*.json` — hand-entered textbook step traces (see below).
- `worked/f84-k2p.md` — the `dnadist` F84 / Kimura definitions from the
  3.697 source (`makev`, `kimquick`, `getbasefreqs`), the printed
  precision, and the two-sequence worked example behind the inline
  values in `tests/dist_v14.rs`.
- `worked/protdist_doc_jtt.json` — the 5-sequence test data from PHYLIP's
  `protdist` documentation read as protein, with the published JTT matrix
  (6 decimals). `{"labels", "sequences", "alphabet": "protein", "jtt"}`.
- `consensus/*.json` — seeded bootstrap tree sets for the support and
  consensus oracles (spec v1.2 §8.1): three unrooted `ape::rmtree` sets
  (NJ splits), two rooted sets (UPGMA clusters), and two `ape::boot.phylo`
  replicate sets of committed alignments (`jc12` JC69, `p8_250` Kimura).
  `generate.R` writes `trees`, `reference` and `prop_clades`;
  `generate_phylip.sh` (via `generate_consensus.sh`) merges `consense`
  from PHYLIP consense. Seeds in each file are the first seed from a
  deterministic search giving no tie at any extended-majority decision
  (the check stops once the tree is fully resolved). Every grouping label
  list is the canonical side: the side not containing `labels[1]` for
  unrooted splits (the side consense happens to print only when its
  species 1 is `labels[1]`; rows are re-canonicalized on parse), the clade
  itself for rooted sets. `consense.<kind>.groups` is the "Sets included"
  table — exactly the non-trivial groupings of `consense.<kind>.newick`
  (support counts are written as branch lengths for majority/extended;
  strict prints no counts). The rejected candidates sit in
  `consense.<kind>.not_included`.
- `worked/consensus_hand.json` — hand-entered 5-taxon 10-tree example
  (spec §8.1 owner gate): 7× `((A,B),C,(D,E))` + 3× `((A,B),E,(C,D))`
  with `expected` strict/majority/extended groupings; `consense` is
  merged by `generate_consensus.sh` like the generated sets and must
  agree with `expected` (owner gate).

## ref/ JSON format

```json
{ "name": "...", "generator": "ape <v> / phangorn <v> | phylip <v>",
  "labels": ["..."], "input": "inputs/x.fasta",
  "distances": { "raw": [[...]], "JC69": [[...]], "K80": [[...]] },
  "nj": { "JC69": "<newick>", "K80": "<newick>" },
  "upgma": { "JC69": "<newick>" },
  "precision": null }
```

`distances` entries are dense n×n row-major arrays of numbers.

## worked/ JSON format

Per-step textbook traces, same field names as `NjStep`/`UpgmaStep`
(spec §4.5). Conventions:

- `matrix`/`distance`/`q` are `{"n": n, "data": [...]}` — `Matrix` row-major.
- `active`/`new_node`/`a`/`b`/`c` hold `NodeId` numbers; `chosen` is the pair
  of **positions** in `active`, `i < j`, lexicographically smallest on ties.
- Actives keep remaining taxa in input order with the new node appended.
- `q`'s diagonal is `0` (unused by the algorithm).
- `new_row` lists distances from the new node to the remaining actives, in
  their `active` order.
- NJ files end with `final_join` (`a`, `b`, `c` are the last three actives in
  order). `step` numbers are 1-based join numbers.

## Regenerating

```sh
python3 fixtures/make_protein_inputs.py  # regenerate inputs/protein/*.fasta
bash fixtures/generate_phylip.sh         # dnadist/protdist + neighbor -> ref/*_phylip.json, ref/protein_*.json,
                                         #   phylip/{f84,k2p}/*.json; then consense -> consensus/*.json
                                         #   + worked/consensus_hand.json
Rscript fixtures/generate.R              # ape/phangorn fixtures -> ref/*.json; second_opinion -> ref/protein_*.json;
                                         #   tree sets + prop_clades -> consensus/*.json
```

Order matters: `generate_phylip.sh` must run **before** `generate.R`, which
reads `ref/protein_*.json` back for its protdist-JTT tie check and merges
`second_opinion` into the same files. `generate_phylip.sh` ends by running
`generate_consensus.sh`, which merges `consense` into
`consensus/*.json` and `worked/consensus_hand.json`; `generate.R` then
regenerates the set files and preserves the committed `consense` block
while the trees are identical, so committed output is stable under either
order. **Exception:** after changing a set's seeds, inputs or sizes, run
`generate.R` *first* so `generate_consensus.sh` merges consense onto the
fresh trees (then `generate_phylip.sh` as usual).
`scripts/ci/fixture-guard.sh` holds the CI order; `FIXTURES=1
./scripts/check.sh` runs both and fails if the outputs drift from what is
committed.

## Tool versions used

ape 5.8.1, phangorn 2.12.1, jsonlite 2.0.0 on R 4.5.2; PHYLIP 3.697
(`dnadist` JC69 via `D D`, Kimura 2-parameter via `D`, F84 via `Y` —
F84, T 2.0 and empirical frequencies are the shipped defaults — and
Kimura at a chosen ratio via `D T <r> Y`; `protdist` JTT by
default, Kimura after 3 `P` toggles — the count is read off the menu each
run; `neighbor` NJ default, `N` toggles UPGMA; `consense` extended
majority by default, strict after one `C`, plain majority rule after two
— toggles are read off the menu each run — `R` for rooted sets).
`dnadist`/`neighbor`/`protdist`/`consense` all report version 3.697;
`dnadist` prints distances to 6 decimals (`output_matrix_d` `%*.6f`).

`seqboot` 3.697 (lab pack 3, v1.4 spec §6.1/§9 — read off the installed
menu 2026-10-27; its output is not committed): defaults are `J`
Bootstrap resampling and `R` = **100 replicates**. There is no seed
default — after `Y` it prompts "Random number seed (must be odd)?" and
rejects 0 or even input until a valid odd seed is given.
