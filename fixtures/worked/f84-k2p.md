# Worked example: `dnadist` F84 and Kimura 2-parameter (v1.4 spec §3.1–§3.3)

Reference: PHYLIP **3.697**, `src/dnadist.c` and `src/seq.c`. The engine
ports these functions in `crates/neophylo-core/src/dist_phylip.rs`; this
file records what they compute and the printed values `tests/dist_v14.rs`
carries inline.

## Definitions

### F84 — `makev`'s general branch (`dnadist.c` `makev`, `!quick` path)

dnadist's default model (menu `D = F84`, `T = 2.0`, `F = Yes`). For a
sequence pair it maximizes the per-site log-likelihood in `tt` by a
fixed-step hill climb (`tt = 0.1`, `delta = 0.1`, halving when the slope
goes negative, stopping at `|delta| <= 2e-7` or `iterationsd = 100`
iterations). Each site contributes

```
slope += w * (z1zz*(bb - aa) + z1xv*(cc - bb)) / (aa*z1zz + bb*z1yy + cc*y1)
```

with `z1 = exp(-xv·tt)`, `z1zz = exp(-tt)`, `z1yy = z1 - z1zz`,
`z1xv = z1·xv`, `y1 = 1 - z1`, `aa = πx·δxy`, `bb = πx` times the
within-class conditional frequency of `y` (`freqar/freqcy/freqgr/freqty`,
zero across classes), `cc = πx·πy`. The printed distance is
`vv = tt * fracchange`.

`xv` and `fracchange` come from `seq.c` `getbasefreqs` at the menu's
`ttratio` (default 2.0): `xi = aa/(aa+bb)` with
`aa = κ·freqr·freqy - πA·πG - πC·πT`, `bb = πA·freqgr + πC·freqty`,
`xv = 1 - xi`; if `xi < 0` the ratio is "impossible with these base
frequencies", `xi` resets to 0 (the feasible floor) and `xv` to 1.
`fracchange = xi·(2πA·freqgr + 2πC·freqty) + xv·(1 - Σπ²)` with each
non-positive π floored to 1e-6 for this term only.

With `F = Yes` (the default) the frequencies are the *empirical* ones
from `dnadist.c` `dnadist_empiricalfreqs` — for unambiguous data, raw
column-weighted base counts over the whole alignment. `getinput`'s
`< 1e-8 -> 1e-6` frequency floor is inside `if (!freqsfrom)` only and
never applies on this path.

### Kimura 2-parameter — `makev`'s `kimquick` branch

Menu: one `D` toggles F84 → "Kimura 2-parameter" (the `F` option leaves
the menu: always **equal** frequencies). The pair's sites are counted as
identical (`num1`), transitions (`num2`) or transversions (the rest);
`tt` starts at 0.1 and climbs on the likelihood of those three counts
with `p1 = exp(-tt)`, `p2 = exp(-xv·tt) - exp(-tt)`,
`p3 = 1 - exp(-xv·tt)`, `q1 = p1 + p2/2 + p3/4`, `q2 = p2/2 + p3/4`,
`q3 = p3/2`, using the same delta-halving and stopping rules; the
distance is again `vv = fracchange * tt`.

This is an ML estimate at a **preset** ratio `T` with equal frequencies —
not the spec §4.3 closed-form K80 in the observed transition and
transversion fractions. The two disagree on the same data by design
(spec §3.3); `tests/parity_phylip_v14.rs` asserts the divergence.

### Inestimable cells

When the climb ends with `delta >= 0.1` (likelihood still rising at the
largest step) dnadist prints `-1.0` with "DIFFERENCE … TOO LARGE TO
ESTIMATE DISTANCE" and sets `baddists`. The engine reports
`Cell::Saturated` for those cells, and the parity fixtures keep the
printed `-1.000000`.

## Printed precision

`output_matrix_d` (`phylip.c`) writes every matrix cell as `%*.6f`:
**6 decimals**. Parity is checked within half a unit of the last printed
decimal (`0.5e-6`), recorded as `"precision": 6` in each
`fixtures/phylip/{f84,k2p}/*.json`.

## Worked two-sequence example

The alignment behind the inline oracle in `tests/dist_v14.rs`
(`pair()`); 58 sites, no gaps or ambiguities, 8 transitions and 5
transversions between the two sequences, empirical base frequencies
A 0.3017, C 0.1983, G 0.2241, T 0.2759:

```text
>SeqA
ATGCCATGACTGGATCGATTCGGAATCGATCGATTGCATCGATCGGATCCTAGCTAAT
>SeqB
ATGTCAAGATTGTATTGAATCAGAATCAATGGACTGCATCGAACGAATCCTGGCTAAT
```
