# NeoPhylo v1.3 (Design system, fonts, responsive layout) Implementation Plan

> **For agentic workers (Devin):** Run each task in its own session with `/neophylo-task v1.3 <N>` (Task 1 adds the `v1.3` mapping). One task → one branch → one PR. Steps use checkbox (`- [ ]`) syntax. Read `AGENTS.md`, this plan's Global Constraints and Review Focus, and the spec sections each task names. Use `./scripts/check.sh quick` while iterating and the default check before pushing. Verify every write with `git diff`.

**Goal:** Make NeoPhylo consistent, light-first, readable at 768 px and up, and identical on every machine, with no change to any scientific result.

**Architecture:** Typed design tokens in `web/src/design/tokens.ts` generate CSS custom properties and are read directly by the tree renderer and exports. Bundled Inter and JetBrains Mono subsets make text measurement deterministic, which enables snapshot tests. `session.ts` is split into focused state modules behind an unchanged API.

**Tech Stack:** As v1.2. Added: Inter and JetBrains Mono (OFL-1.1) `woff2` subsets; fonttools `pyftsubset` (pinned, build-time only); Playwright `toHaveScreenshot` (already a dependency).

**Spec:** `docs/superpowers/specs/2026-10-21-neophylo-v1.3-design-system-design.md` (§ below). Earlier specs still apply where not overridden.

## Global Constraints

- **No scientific change:** engine, parity, golden-hash and lesson-premise tests pass unmodified. No files under `crates/` change, except comments.
- **Old links:** `web/src/state/__fixtures__/v1-urls.json` and `v2-urls.json` restore identically.
- **Tokens only:** no literal colors or font sizes outside `web/src/design/tokens.ts` (the discipline test from Task 3).
- **Type scale (px):** 12, 14, 16, 20, 24, 32; minimum 12 px anywhere. **Spacing:** 4, 8, 12, 16, 24, 32, 48. **Radii:** 4, 8, 12.
- **Contrast:** text ≥ 4.5:1; large text, interface components and graphics ≥ 3:1, in both themes.
- **Default theme:** light, regardless of the operating-system setting.
- **Device-local preferences** (try/catch, never in URLs): `neophylo.theme`, `neophylo.presenter`, `neophylo.tourSeen`.
- **Fonts:** Inter 400/500/600 and JetBrains Mono 400; subsets `latin`, `latin-ext`, `greek`, `cyrillic`; features `kern` and `tnum` kept; ≤ 200 KB total; `font-display: block`; layout waits up to 3 s for fonts, then re-lays out once on arrival.
- **Breakpoints:** wide ≥ 1280, medium 1024–1279, narrow 768–1023, compact < 768.
- **Layout invariants:**
  - tree panels at natural height (28 px per leaf + padding)
  - horizontal scroll only inside tree panels; inner vertical scroll only above 40 leaves
  - stepper pinned to the bottom; no sideways page scrolling
  - dialogs become full-screen sheets below 1024
- **Touch targets:** ≥ 40×40 px under `(pointer: coarse)`. **Presenter mode:** type and spacing × 1.5.
- **Exact texts:** spec §6.8 and §6.9, verbatim.
- **Snapshots:**
  - Chromium only, animations disabled, `maxDiffPixelRatio` 0.001
  - viewports 1920×1080, 1024×768, 768×1024; both themes
  - baselines in `web/e2e/__screenshots__/`, owned by the owner via CODEOWNERS
  - **any baseline change needs owner approval;** the PR description lists the changed scenes
- Review evidence screenshots go in PR comments, never committed (snapshot baselines are the only committed images, besides README media).

## Review Focus

1. **Taxon names outside the bundled subsets** (Chinese characters, emoji, Arabic) render with a system fallback, are measured as actually rendered (no overlaps), and exporting warns "Some names use characters outside the bundled fonts and may look different in other programs." → Tasks 4, 15.
2. **Browser zoom at 200%** (a 1280 px window behaves like 640 CSS px): compact layout, no sideways page scroll, stepper visible, all leaves reachable. → Task 9.
3. **Blocked storage** (private mode, storage exceptions): theme, presenter and tour fall back to their defaults without errors; the tour shows at most once per page session. → Tasks 6, 12.
4. **Switching theme or presenter mode mid-task** (a dialog open, a bootstrap run in progress): no state is lost, the run continues, the dialog stays open and re-styled. → Tasks 6, 11.
5. **Rotating a tablet mid-lesson** (768×1024 ↔ 1024×768): the layout reflows, step and selection are kept, an open drawer stays consistent (open and focused, or closed with focus returned). → Task 9.
