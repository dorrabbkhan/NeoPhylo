# NeoPhylo v1.4c (matrix input, lesson library and worksheets) Implementation Plan

> **For agentic workers (Devin):** Run each task in its own session with `/neophylo-task v1.4c <N>` (Task 1 adds the `v1.4c` mapping). One task → one branch → one PR. Steps use checkbox (`- [ ]`) syntax. Read `AGENTS.md`, this plan's Global Constraints and Review Focus, and the spec sections each task names. Use `./scripts/check.sh quick` while iterating and the default check before pushing. Verify every write with `git diff`. Never force-push; never touch `.claude/`.

**Goal:** Let users start from a distance matrix (file, paste or grid, in the sandbox, exercises and the editor), and turn lessons and labs into a library with generated worksheets, engine-computed answer keys and an instructor guide, with no change to existing results.

**Architecture:** A matrix is a third kind of exercise data (`ExerciseData::Matrix`) and a third analysis origin. The engine parses it into a `DistanceInput` (names + strict lower triangle) and turns it into the existing `DistanceMatrix` with a new `DistModel::Supplied`, so `build_tree`, traces, the stepper and exports run unchanged. Alignment-only panels switch off through one helper, `hasAlignment(session)`. Worksheets and answer keys are pure functions of an exercise and its engine trace, rendered on lazy-loaded pages next to the existing lab pages.

**Tech Stack:** As v1.4b. No new runtime dependency except, if needed, one small QR encoder (Task 11 rule).

**Spec:** `docs/superpowers/specs/2026-11-14-neophylo-v1.4c-matrix-and-library-design.md`. Earlier specs still apply where not overridden.

**Decided in this plan (spec §11 items and interface choices):**
- **`DistModel::Supplied`** (JSON `"Supplied"`, `name()` = `"supplied"`): the model of every `DistanceMatrix` built from a `DistanceInput`. `supports()` is false for both alphabets, so `compute`/`compute_filtered` already refuse it through the existing `ModelAlphabetMismatch` path; it is never accepted as `analysis.correction`.
- **`DistanceInput { names: Vec<String>, lower: Vec<f64> }`**, strict lower triangle in row order. Structural problems are `NeoError::InvalidMatrix { row: String, col: String, msg: String }` (taxon names; empty strings when not about one cell). File-syntax problems stay `NeoError::Parse { line, col, msg }`.
- **Matrix exercise files:** `data: { "kind": "matrix", "names": [...], "lower": [...], "source": {...} }`; `analysis` holds only `method`. The loader sets `correction` to `Supplied`; a file that sets `correction`, `kappa` or `site_filter` on a matrix exercise is refused with that field path. `alphabet` stays required and names what the distances were computed from; the UI shows "Distance matrix" instead of the alphabet badge for matrix data.
- **Lesson metadata:** optional `meta: { objectives: [string], minutes: integer ≥ 1, level: "intro"|"intermediate"|"advanced", prepares_for: [id], hand_steps?: integer ≥ 1 }`. `hand_steps` overrides the paper worksheet's hand-worked join count.
- **`parse_meg`** keeps reading sequences only. Its distance-file refusal text changes from "…planned for v1.4c" to "this .meg file holds a distance matrix; open it as a distance matrix". This is the only existing test assertion v1.4c edits (Task 4), and the change is recorded in `docs/decisions.md`.
- **Format detection** lives in Rust: `detect_matrix_format(text) -> Option<MatrixFormat>`; the import panel calls it before the alignment parsers.
- **Grid cap:** the typing grid holds 3–30 taxa; files and paste accept up to `MAX_TAXA` (200).
- **Paper worksheets:** only for exercises with ≤ 8 taxa. Hand-worked joins: all for `n` ≤ 6, the first two for 7–8, unless `meta.hand_steps` says otherwise.
- **Routes** (all lazy chunks in `Root.tsx`): `?library` (optional `&type=lessons|phylip|mega|datasets`), `?worksheet=<id>&kind=paper|app`, `?key=<id>&kind=paper|app`, `?guide`. A custom exercise uses `<id>` = `custom` with the exercise in `#x=`. `?labs` renders the library with `type=phylip,mega` preselected; `?lab=<id>` is unchanged.
- **Answer-key gate:** `sessionStorage["neophylo.instructor"] = "1"` after the click, every access in `try/catch`; when storage fails, the dialog shows each time.
- **URLs:** `UrlState.imported.matrix?: DistanceInput`; `v` stays 3 (an optional field). New corpus `web/src/state/__fixtures__/v3-matrix-urls.json`.
- **Lesson ids:** `nj-by-hand`, `upgma-vs-nj-matrix`.

## Global Constraints

- **No existing number changes:** engine, parity, golden-hash, bootstrap and lesson-premise tests pass unmodified (one message assertion in the `.meg` tests excepted, above). Existing fixtures are not edited; new ones go in their own PRs (CI fixture guard: a PR that modifies `fixtures/` cannot also change code).
- **Old files and links:** `exercises/*.json`, `exercises/labs/*.json` (schema 2–4) load unchanged; `v1-urls.json`, `v2-urls.json`, `v3-urls.json` restore identically.
- **No outside network request from the browser.** v1.4c adds none.
- **Science in Rust only:** matrix parsing, validation, detection, additive matrices, ties and "closest pair" checks live in `crates/neophylo-core`. TypeScript draws, dispatches and lays out.
- **Answer keys are never typed:** every number on a key comes from the engine trace at render time. No content file contains a key value.
- **Determinism:** `libm` for all math; no `Math.random`.
- **Engine never panics:** any text into any parser, any `DistanceInput`, returns `Ok` or `NeoError`.
- **New proptests go in new functions** (saved `cc` seeds of existing strategies must stay valid).
- **New schema keys are pinned for `null` and array values** (serde treats `null` as absent for `Option`).
- **Lesson content rules:** no spoilers before the student acts; no hard-coded data numbers in new text; support is never a probability.
- **Tokens only:** no literal colors or font sizes outside `web/src/design/tokens.ts`. Type scale 12–32 px.
- **Touch targets:** ≥ 40×40 px under `(pointer: coarse)`, measured with `hasTouch`, including plain links and grid cells' controls.
- **Initial-JS budget unchanged:** library, worksheet, key and guide pages are lazy chunks; the perf-load e2e test passes without raising its budget.
- **Owner-only:** fixture approval, snapshot baselines, lesson/guide/handout review sign-off, the release tag.
- **Snapshots:** Chromium only, `maxDiffPixelRatio` 0.001, viewports 1920×1080, 1024×768, 768×1024, both themes. Baselines owner-approved. Review evidence screenshots go in PR comments, never committed.

## Review Focus

1. **Pasted matrices from PDFs and spreadsheets:** decimal commas (`0,25`), Unicode minus (`−0.1`), tabs mixed with spaces, a trailing blank line, a header row, names with spaces, a square matrix with a blank upper triangle. Each parses to the right values or asks a question; none is silently misread (a decimal comma never becomes two cells). → Task 4.
2. **Bad names:** duplicate names, an empty name, and two names that become equal after PHYLIP's 10-character truncation → `InvalidMatrix` naming both. → Tasks 3, 4.
3. **Editing the grid mid-session:** clearing a cell, adding or removing a taxon while the stepper is past step 0 → the tree area returns to "complete the matrix" with the reason; no stale tree, Q matrix or step index survives. → Task 8.
4. **Leaving a matrix session:** importing an alignment, opening a lesson or a `ds=` dataset after a matrix session (and the reverse) restores or hides every alignment-only panel correctly, and the share link carries only the current data. → Tasks 7, 8.
5. **Worksheet edge cases:** an exercise with a tie, with a zero distance, or with exactly 3 taxa (one join) → the sheet and key render; ties list every tied pair as correct. → Task 11.

Each line is pinned by a named test in the owning task.
