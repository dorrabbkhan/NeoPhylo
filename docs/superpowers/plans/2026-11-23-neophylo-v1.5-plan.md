# NeoPhylo v1.5 (navigation redesign, classroom delivery and assessment) Implementation Plan

> **For agentic workers (Devin):** Run each task in its own session with `/neophylo-task v1.5 <N>` (Task 1 adds the `v1.5` mapping). One task → one branch → one PR. Steps use checkbox (`- [ ]`) syntax. Read `AGENTS.md`, this plan's Global Constraints and Review Focus, and the spec sections each task names. Use `./scripts/check.sh quick` while iterating and the default check before pushing. Verify every write with `git diff`. Never force-push; never touch `.claude/`; never post a review approval on your own PR; never install browsers. DOM, ARIA or layout changes run their affected e2e specs on Chromium, Firefox and WebKit before pushing.

**Goal:** A redesigned header and polished UI, then instructor-ready assessment with no accounts and no server: assignment links that give each student their own variant, auto-checked tasks, completion codes that carry the student's answers, an offline Grade page that grades a whole class from the LMS export, embed mode, and a published accessibility report.

**Architecture:** Milestone 1 rebuilds the header as an icon tray plus a mode pill (two PRs, each with its owner baseline round). The engine gains an `assess` module: an assignment wraps existing content (built-in lesson, lab, reading set, or an editor exercise); a variant comes from `hash(assignment id, normalised student id)` with declared premises and a retry loop; every gradable task's answer is computed from the variant; a completion code packs the student's answers; `grade` rebuilds the variant and checks them. The web side adds the `#a=` student flow, a builder in the editor, and a lazy-loaded Grade page (`?grade`) that reads LMS CSVs in the browser.

**Tech Stack:** As v1.4d. No new runtime JS dependency. Icons ship as a static SVG sprite file, not JS.

**Spec:** `docs/superpowers/specs/2026-11-18-neophylo-v1.5-classroom-assessment-design.md` (revised and approved 2026-11-23). Mockups: `docs/superpowers/specs/2026-11-23-v1.5-nav-mockups/`. Earlier specs still apply where not overridden.

**Decided in this plan (spec §14 items and interface choices):**
- **Hash:** FNV-1a 64-bit over UTF-8 bytes, written out in `assess/hash.rs` (no dependency), used for the variant seed (`fnv1a64(assignment.id + "\u{1f}" + normalised_id)`), retry seeds (`fnv1a64(le_bytes(seed) ++ le_bytes(k))`), `content_hash` (hex of the hash of the content file's exact bytes) and the assignment fingerprint (low 20 bits of the hash of the canonical assignment JSON). Pinned by known-answer tests.
- **Checksum:** CRC-16/CCITT-FALSE over the packed payload bits, appended as 4 base32 symbols. A single changed symbol is a burst of at most 5 bits, so it is always detected (spec §1 criterion 2).
- **Code text:** `NP1-` + Crockford base32 (no I, L, O, U; decode treats `i`/`l` as 1 and `o` as 0, case-insensitive, ignores `-` and spaces) grouped by 5. Bit layout: the task's own (Task 5), within spec §5.4; versions first so later layouts can change.
- **Module layout:** `crates/neophylo-core/src/assess/{mod,hash,assignment,premise,variant,task,precision,code,grade}.rs`. Errors: new `NeoError::InvalidAssignment { field: String, msg: String }` and `NeoError::InvalidCode { reason: String }`.
- **Display precision:** `assess/precision.rs` holds the table (quantity → decimals) and is exported to TS as a generated constant; the web formatters for Q-values, branch lengths and distances read it, and a web test fails if any formatter disagrees. A numeric answer is correct when it rounds (half away from zero) to the engine value at that precision.
- **Generator version:** `GENERATOR_VERSION: u8 = 1`. Golden variant files live in `crates/neophylo-core/tests/assess_golden/` (not `fixtures/`, so code PRs can carry them); changing an existing golden file is an owner gate like a fixture.
- **Routes:** `#a=` (lz-compressed `{ v: 1, assignment }`, like `#x=`/`#r=`), `?grade` (Grade page), `?embed` (embed mode, also set when `window.top !== window.self`). File extension `.neophylo-assignment.json`. Local storage keys prefixed `neophylo:a:` (progress, codes) and `neophylo:draft:` (editor autosave).
- **Icons:** one outline set drawn for NeoPhylo or taken from Lucide (ISC), about 20 symbols in `web/public/icons/ui.svg`, used as `<svg><use href="…/ui.svg#id"/></svg>`. Lucide, if used, is listed in THIRD_PARTY_NOTICES and the Licenses page. `web/public/icons.svg` (unused Vite template) is deleted after a grep shows no reference.
- **CHANGELOG.md:** repo root, Keep-a-Changelog headings, one section per release v1.0–v1.4d written in Task 1 from `docs/roadmap.md`, `## [Unreleased]` for v1.5.

## Global Constraints

- **No existing number changes:** engine, parity, golden-hash, bootstrap, lesson-premise and reading tests pass unmodified. Existing `fixtures/` files are not edited (fixture guard).
- **Old files and links:** `exercises/**/*.json` and the `v1`–`v3` URL corpora, `#x=`, `#r=`, `?read=`, `?lab=`, `?library`, `?worksheet=`, `?key=` load and restore unchanged.
- **Science in Rust only:** variants, premises, every task answer, checking, code packing and grading live in `crates/neophylo-core`. TypeScript reads CSVs, maps columns, draws and dispatches. No `Math.random`.
- **Engine never panics:** any text into `load_assignment`, `decode_code` or `grade`, and any student id, returns `Ok` or `NeoError`.
- **Determinism across platforms:** same assignment + id → same variant and same answers in native Rust, wasm and every browser (golden tests).
- **New proptests go in new functions;** new schema keys pinned for `null` and array values (serde gap); a new fuzz target ships with committed seeds in `fuzz/seeds/<target>/`.
- **Nothing leaves the browser:** no outside network request; the Grade page never uploads; student data is never written to storage by the Grade page.
- **Tokens only:** no literal colours or font sizes outside `web/src/design/tokens.ts`; type scale 12–32 px.
- **Touch:** every new or restyled interactive element ≥ 44 × 44 px under `(pointer: coarse)` (header) or ≥ 40 × 40 px (page content, existing rule), measured with `hasTouch`, plain `<a>` links included; touch e2e uses CDP touch events and `elementFromPoint`.
- **Initial-JS budget:** headroom is about 3.4 KB gzip (`scripts/check-bundle-size.sh`). The header may add at most 2 KB; the assignment flow, builder and Grade page are lazy chunks; the icon sprite is a static file.
- **Owner-only:** snapshot baselines, golden variant files, guide and lesson wording, the binomial-bound number, the audit and ACR sign-off, the release tag.
- **Snapshots:** Chromium only, `maxDiffPixelRatio` 0.001, viewports 1920×1080, 1024×768, 768×1024 (plus 360×740 where a phone layout exists), both themes. Review evidence screenshots in PR comments, never committed.

## Review Focus

1. **A student reloads or switches browsers mid-assignment:** progress restores in the same browser; a different browser starts fresh but the same ID gives the same variant; a Finish in each yields two codes and the grader counts the latest Finish and lists the other. → Tasks 8, 9 (`assignment_resume.spec.ts`, `grade.test.ts` "two codes, latest counts").
2. **IDs typed differently:** `" Ana.Lopez@Uni.edu "` vs `ana.lopez@uni.edu` → same variant; a non-ASCII ID (`josé`) and an empty ID → empty is refused at entry, `josé` works and grades. → Tasks 4, 8 (`assess_variant::normalisation_is_stable`, `assignment_flow.spec.ts` "id normalisation").
3. **Real LMS exports are messy:** BOM, `;` delimiters (European Excel), quoted newlines inside answers, the code pasted with surrounding text or line breaks, duplicate header names → codes still found by the `NP1-` prefix, nothing crashes, unreadable rows are flagged not dropped. → Task 9 (`csv.test.ts` "messy exports").
4. **Header at awkward widths and zoom:** 1024–1279 px with the longest lesson title, 200 % browser zoom at 1280, presenter mode at 1920 → nothing overlaps, title ellipsis, every destination still reachable. → Task 2 (`header-nav.spec.ts` "awkward widths").
5. **Embedded with storage blocked:** inside an LMS iframe with third-party storage blocked, the student can still finish and copy a code; the page says progress won't survive a reload. → Task 8 (`embed.spec.ts` "storage blocked").

Each line is pinned by a named test in the owning task.

### Task 4: Engine — hash, assignment model, premises, variants, gradable tasks

Spec §4, §5.1–5.3, §5.6 (engine side).

**Files:**
- Create: `crates/neophylo-core/src/assess/{mod,hash,assignment,premise,variant,task,precision}.rs`, `crates/neophylo-core/tests/{assess_hash,assess_variant,assess_variant_props,assess_task}.rs`

**Interfaces:**
- Produces:
  - `fn fnv1a64(bytes: &[u8]) -> u64`; `fn normalise_id(raw: &str, rule: IdRule) -> Result<String, NeoError>` (`IdRule::TrimLower` default: trim Unicode whitespace, `to_lowercase`; empty after trim → `InvalidAssignment { field: "student_id" }`); `fn variant_seed(assignment_id: &str, normalised_id: &str) -> u64`.
  - `enum Premise { TieFree, ClosestPairNotFirst, UpgmaDiffersFromNj, NjRecoversTrueTree, ReadingValid }`; `fn premises_hold(content: &Content, premises: &[Premise]) -> Result<bool, NeoError>`.
  - `enum Content { Exercise(Exercise), Reading(ReadingSet) }`; `struct Variant { content: Content, retry: u8, fell_back: bool }`; `fn make_variant(base: &Content, premises: &[Premise], seed: u64, vary: bool) -> Result<Variant, NeoError>` (retries `k = 1..=50` per spec §5.2; `fell_back` true when none held; `vary == false` returns the base with the bootstrap seed only).
  - `enum TaskRef { PredictPair { step: u32 }, PredictBranch, Numeric { step: u32, quantity: Quantity, role: PairRole }, Reading { item: usize } }`; `enum Quantity { QValue, BranchLength, NewDistance, CorrectedDistance }`; `enum PairRole { Chosen, ClosestRaw, ChosenFirstToNew, … }` (roles, never names; the task lists the minimal set the builder needs); `enum TaskAnswer { Pair(u16, u16), Branch(CladeKey), Number(i64), Reading(Response) }` (numbers as scaled integers at display precision).
