# NeoPhylo v1.4 (Instructor kit and PHYLIP lab packs) Implementation Plan

> **For agentic workers (Devin):** Run each task in its own session with `/neophylo-task v1.4 <N>` (Task 1 adds the `v1.4` mapping). One task → one branch → one PR. Steps use checkbox (`- [ ]`) syntax. Read `AGENTS.md`, this plan's Global Constraints and Review Focus, and the spec sections each task names. Use `./scripts/check.sh quick` while iterating and the default check before pushing. Verify every write with `git diff`.

**Goal:** Let an instructor build, save and share their own exercises without editing JSON, and give PHYLIP teachers ready-made lab packs that reproduce `dnadist` and `protdist` chains, with two new DNA models that match `dnadist` and no change to existing results.

**Architecture:** Tree editing operations live in a new engine module (`edit.rs`) so the drag canvas, the Newick view and the branch-length table all render from one engine-validated tree model. The two new distance models are added to the existing `DistModel` enum; F84 is also added to the simulator, with instructor-set base frequencies. The exercise format moves to schema version 3 with an optional analysis ratio and simulation base frequencies, and version 1 and 2 files still load. Lab packs are exercise files with an extra `lab` block, rendered by an in-app lab page with a print stylesheet.

**Tech Stack:** As v1.3. Added: none. Fixtures from `fixtures/generate_phylip.sh` (`dnadist`, `neighbor`), pinned as v1.1–v1.3 were.

**Spec:** `docs/superpowers/specs/2026-10-26-neophylo-v1.4-instructor-kit-design.md`. Earlier specs still apply where not overridden.

**Decided with the owner (2026-10-26), now reflected in the spec:**
- JSON identifiers follow the existing uppercase convention: `F84` and `K2P_PHYLIP`. Reason: `analysis.correction` already uses `"Kimura"` for the **protein** Kimura correction (`dist.rs`, `DistModel::Kimura`), so a DNA model with a similar name would collide or confuse. The UI label for the second model is "K2P (dnadist, κ = 2.0)".
- F84 simulation takes **instructor-set base frequencies** (A, C, G, T; must be positive and sum to 1 within 1e-6; default equal). Estimation still uses observed frequencies, as `dnadist` does by default.
- The exercise schema moves to `schema_version` 3, adding `analysis.kappa` (required for `K2P_PHYLIP`, default 2.0 in the editor) and an optional `sim.base_freqs` (for `F84`).

## Global Constraints

- **No existing number changes:** engine, parity, golden-hash and lesson-premise tests pass unmodified. Existing fixtures and golden files are not edited; new ones are added in their own commits (CI fixture guard).
- **Old files and links:** `exercises/*.json` (schema 2) load unchanged. `web/src/state/__fixtures__/v1-urls.json` and `v2-urls.json` restore identically.
- **Naming:** `DistModel::F84`, `DistModel::K2pPhylip { ratio: f64 }`; JSON `"F84"`, `"K2P_PHYLIP"`. Existing `"K80"` and `"Kimura"` (protein) are unchanged.
- **Science in Rust only:** every tree-structure change goes through `crates/neophylo-core/src/edit.rs`. TypeScript computes coordinates only (via the existing `layout` functions).
- **Determinism:** `libm` for all math; seeded `ChaCha8Rng`; fixed consumption order in the F84 simulator; no `Math.random`.
- **Engine never panics:** invalid `ratio`, `kappa`, base frequencies, lengths or edits return `NeoError`.
- **Tokens only:** no literal colors or font sizes outside `web/src/design/tokens.ts`. Type scale 12–32 px, minimum 12 px.
- **Touch targets:** ≥ 40×40 px under `(pointer: coarse)`.
- **Device-local storage:** try/catch, never required, never in URLs. Editor drafts may use it for convenience only.
- **Owner-only:** fixture changes, snapshot baseline changes, lab content review sign-off, and the release tag. The agent never tags.
- **Snapshots:** Chromium only, `maxDiffPixelRatio` 0.001, viewports 1920×1080, 1024×768, 768×1024, both themes. Baselines in `web/e2e/__screenshots__/`, owner-approved.
- Review evidence screenshots go in PR comments, never committed.

## Review Focus

1. **Invalid `ratio`, `kappa` or base frequencies** (0, negative, NaN, infinity, extremely large, frequencies that are zero or do not sum to 1): `NeoError` from the engine, a readable message in the editor, never a panic or a NaN distance. → Tasks 2, 4, 6, 10.
2. **Saturation under F84 and K2P_PHYLIP** (log argument ≤ 0): the cell is `Saturated`, NJ and UPGMA refuse the matrix, and the lesson shows the existing saturation feedback. → Task 2.
3. **Drag-built trees that are not valid exercises** (duplicate taxon names, zero or one taxon, negative branch length, a node with one child): refused with the reason, undo restores the previous valid tree, and the saved file never fails schema validation silently. → Tasks 5, 9, 10.
4. **Shared links longer than the limit, and old files after the schema bump:** the editor says the link is too long and offers the file instead of truncating; schema 1 and 2 files and old `#x=` links still load identically. → Tasks 6, 7.
5. **"Load this lab" over unsaved editor work:** the instructor is asked before the editor's current exercise is replaced; declining keeps the work. → Task 11.

Each line is pinned by a named test in the owning task.
