# NeoPhylo v1.4d (tree reading) Implementation Plan

> **For agentic workers (Devin):** Run each task in its own session with `/neophylo-task v1.4d <N>` (Task 1 adds the `v1.4d` mapping). One task → one branch → one PR. Steps use checkbox (`- [ ]`) syntax. Read `AGENTS.md`, this plan's Global Constraints and Review Focus, and the spec sections each task names. Use `./scripts/check.sh quick` while iterating and the default check before pushing. Verify every write with `git diff`. Never force-push; never touch `.claude/`; never post a review approval on your own PR; never install browsers.

**Goal:** A separate "Reading trees" area where intro-biology students answer tree-reading questions (relatedness, MRCA, clades, rotation, node order, traits) on real-organism trees in several drawing styles, with every answer computed by the engine, an editor mode to author reading sets, four lessons, two before/after forms, a format-coverage set mirroring the published instruments, and paper worksheets with keys.

**Architecture:** A new file type, the **reading set** (`kind: "reading"`), parsed and validated by a new engine module `crates/neophylo-core/src/reading/`. The engine identifies every node by its tip set (clade), computes every answer and explanation, checks responses, and provides seeded variant transforms for v1.5. The web side adds pure layout functions for the new drawing styles, a `ReadingTree` SVG component with tap/keyboard selection, a lazy-loaded reading area (`?read=`, `#r=`), an editor mode, and reading-set worksheets reusing the v1.4c worksheet pages.

**Tech Stack:** As v1.4c. No new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-11-18-neophylo-v1.4d-tree-reading-design.md`. Earlier specs still apply where not overridden.

**Decided in this plan (spec §11 items and interface choices):**
- **Clade keys:** a node is named in files and across the wasm boundary by `CladeKey` = its tips' labels, sorted (Unicode code-point order), deduplicated, as a JSON array; the string `"root"` is accepted in files and resolved to the full tip set. Branches are named by the clade below them.
- **Module layout:** `reading/mod.rs` (re-exports), `reading/query.rs` (tree queries), `reading/traits.rs` (marks → states), `reading/set.rs` (file types, load, validate), `reading/answer.rs` (answers, explanations, `check`), `reading/variant.rs` (seeded transforms). RNG: `ChaCha8Rng` as in `sim.rs`.
- **Error:** new `NeoError::InvalidReading { item: String, field: String, msg: String }` (`item` = item id or `""` for set-level problems); `Display` "reading set item {item}, {field}: {msg}" or "reading set, {field}: {msg}".
- **Limits:** 3–40 tips per tree; 1–4 trees per item; tips-up trees ≤ 12 tips; 1–60 items per set; at most 20 traits per tree.
- **Taxon names in item text:** item text refers to taxa only through placeholders `{a}`, `{b}`, `{c}` (bound to the item's `a`, `b`, `c` fields) and `{set}` (the item's `tips` list, rendered as a comma list). A repo test (Task 12) fails when built-in item text contains a literal tip label of a tree whose taxa are in `taxa_pool`, so relabelling variants (v1.5) stay correct.
- **Explanations** are built in Rust from fixed English templates in `answer.rs`, one per question type, filled with names and node letters (or "the node joining {x} and {y}" when unlettered). No numbers other than node ages from `times`.
- **Name abbreviation:** labels longer than 18 characters are shown abbreviated by the layout (first 16 characters + "…") with the full name in `<title>` and the text description; never in item text.
- **Rotation animation:** 300 ms ease-in-out swap; none under `prefers-reduced-motion`.
- **IDs and routes:** built-in sets live in `exercises/reading/` with ids prefixed `trees-` (`trees-reading-a-tree`, `trees-rotation`, `trees-closest-relatives`, `trees-clades-traits`, `trees-form-a`, `trees-form-b`); coverage items in `exercises/reading/coverage/` (ids `cov-…`), not listed in the library. Routes: `?read=<id>` (built-in or `cov-…`), `#r=` (shared set, lz-compressed like `#x=`, payload `{ v: 1, set }`), `?library&type=reading`, `?worksheet=<id>&kind=paper` and `?key=<id>&kind=paper` accept reading ids. File extension `.neophylo-reading.json`.
- **Library:** `TypeKey` gains `"reading"` (label "Tree reading"); header gains a "Reading trees" link to `?library&type=reading`.
- **Oracle scope:** R (`ape`/`phangorn` plus a separate `nodepath`-based script) computes MRCA, monophyly, rooted same-relationships, restriction, sister sets, ancestry pairs, trait states and trait-change counts on a fixture corpus; built-in content is checked by engine tests (Task 12), not by fixtures, so content edits never touch `fixtures/`.

## Global Constraints

- **No existing number changes:** engine, parity, golden-hash, bootstrap and lesson-premise tests pass unmodified. Existing fixtures are not edited; new ones go in their own PR (CI fixture guard: a PR that modifies `fixtures/` cannot also change code).
- **Existing views unchanged except the header and the library;** their regenerated baselines are owner-approved in Task 9 only. The sandbox `TreeView`, its layout and its exports do not change.
- **Old files and links:** `exercises/*.json`, `exercises/labs/*.json` and the `v1`–`v3` URL corpora load and restore unchanged.
- **No outside network request from the browser.**
- **Science in Rust only:** every answer, accepted set, validity check, explanation and variant lives in `crates/neophylo-core`. TypeScript draws, dispatches and lays out.
- **Answers are never typed into content files** except `concept` answers and `two_tier` reasons, which are labelled "authored answer" wherever shown.
- **Determinism:** `libm` for math; `ChaCha8Rng` for seeds; no `Math.random`.
- **Engine never panics:** any text into `load_reading_set` and any `Response` into `check` returns `Ok` or `NeoError`.
- **New proptests go in new functions;** new schema keys pinned for `null` and array values (serde gap).
- **Lesson content rules:** no spoilers before the student acts; no hand-typed numbers; support never read as probability; no published instrument's wording or figures.
- **Tokens only:** no literal colors or font sizes outside `web/src/design/tokens.ts`; type scale 12–32 px; trait gain and loss differ by shape, not color alone.
- **Touch:** tap only, no drag in the reading area; node and tip hit areas ≥ 40×40 px under `(pointer: coarse)`, measured with `hasTouch`; touch e2e uses CDP touch events and `elementFromPoint`.
- **Initial-JS budget unchanged:** reading area, editor reading mode and reading worksheets are lazy chunks.
- **Owner-only:** fixture approval, snapshot baselines, content review sign-off, the release tag.
- **Snapshots:** Chromium only, `maxDiffPixelRatio` 0.001, viewports 1920×1080, 1024×768, 768×1024 (plus 360×740 for the reading area), both themes. Review evidence screenshots in PR comments, never committed.

## Review Focus

1. **Polytomies everywhere:** a 3-way polytomy in `closest_relative` (pairwise form must answer "equally close"), `mrca`, `same_relationships` (a polytomy vs a resolved tree is *different*), `order_nodes` and layout (children evenly spaced, no overlap). → Tasks 3, 4, 6.
2. **Same tree, different drawing:** an item whose trees are identical but drawn in different shapes, orientations and rotations → `which_differs` answer "all show the same"; a test renders every style of one tree and the engine answer never changes. → Tasks 4, 6.
3. **Order without times:** `order_nodes` on nodes from different lineages accepts every order consistent with ancestry and rejects one that puts a descendant before its ancestor; with `times`, exactly one order. → Task 3.
4. **Mid-question tree changes:** rotating nodes after selecting a node or tips keeps the selection on the same clade (selection is stored as a `CladeKey`, never a screen position); Back/Next keeps each item's response. → Task 8.
5. **Long and odd names on narrow screens:** 30-character names, names with spaces and apostrophes, 12-tip tips-up tree at 360 px → no clipping, text ≥ 12 px, panel scrolls with a cue. → Tasks 6, 7.

Each line is pinned by a named test in the owning task.

  - `pub fn mrca(tree: &Tree, tips: &[String]) -> Result<NodeId, NeoError>` (unknown tip → `InvalidReading` with `field` "tips").

  - `pub fn same_relationships(a: &Tree, b: &Tree) -> Result<bool, NeoError>` (different tip sets → `InvalidReading`).
  - `pub fn restrict(tree: &Tree, tips: &[String]) -> Result<Tree, NeoError>` (prune and suppress unary nodes).
  - `pub fn is_ancestor(tree: &Tree, anc: NodeId, desc: NodeId) -> bool`; `pub fn order_consistent(tree: &Tree, order: &[NodeId], ages: Option<&BTreeMap<CladeKey, f64>>) -> bool` (without ages: no node appears after one of its descendants; with ages: non-increasing ages, ties refused at load in Task 4).
  - `pub fn count_clades(tree: &Tree) -> u32` (internal nodes including the root).
  - `reading::traits`: `pub struct Mark { pub on: CladeKey, pub trait_name: String, pub change: Change }` (serde `trait` ↔ `trait_name`), `pub enum Change { Gain, Loss }`; `pub fn tip_states(tree: &Tree, marks: &[Mark], trait_name: &str) -> Result<BTreeMap<String, bool>, NeoError>` (root state false; marks applied root to tip; order of marks on one branch as listed); `pub fn change_count(marks: &[Mark], trait_name: &str) -> u32`; `pub fn origins_shared(tree: &Tree, marks: &[Mark], trait_name: &str, x: &str, y: &str) -> Result<bool, NeoError>` (one gain on both root paths).
  - `NeoError::InvalidReading` as decided above.
