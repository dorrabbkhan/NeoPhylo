# NeoPhylo v1.1: Protein support and PHYLIP-format I/O, design spec

Status: Draft for review · Date: 2026-10-16 · Repo path: `docs/superpowers/specs/2026-10-16-neophylo-v1.1-protein-design.md`
Builds on: `2026-10-15-neophylo-design.md` (the "v1 spec"; § numbers prefixed "v1 §").

## 1. Purpose and decision record

v1.1 lets NeoPhylo replace the most common PHYLIP teaching workflow, **`protdist` → `neighbor` on protein
sequences**, with every step explained.

Evidence behind this scope:
- **User interview** (a former biochem student): her lab ran `protdist` then `neighbor`; the workflow was clunky;
  she "didn't understand how trees were built, just got trees"; NeoPhylo "would have helped."
- **Published lab handouts** use the same sequence and often add `seqboot`/`consense`. Bootstrap is the next
  release (v1.2).
- **`protdist`'s default model is Jones-Taylor-Thornton (JTT)**, so students accepting defaults got JTT distances.
  Kimura's formula alone would give different numbers from an existing lab, so **JTT is required**.

**Architecture choice: hybrid.** DNA's validated closed-form distances and DNA simulation stay
**byte-for-byte unchanged**. A new general substitution-model module (`model`) carries JTT and becomes the foundation
for later work: PAM/PMB, gamma rates, and a likelihood (Felsenstein pruning) teaching module.

## 2. Scope

### 2.1 In v1.1
- A protein alphabet with auto-detection and manual override.
- PHYLIP-format alignment import (sequential/interleaved; strict/relaxed names), and distance-matrix export in
  `neighbor` input format.
- Protein distances: p-distance, Kimura (1983), and JTT (maximum likelihood per pair).
- JTT sequence simulation along a true tree.
- A "How was this distance computed?" pair panel, with the likelihood curve for JTT.
- Two lessons: a simulated protein lesson, and a real cytochrome c lesson with a reference classification.
- A "Coming from PHYLIP?" help panel. R-script export for protein models.

### 2.2 Non-goals (v1.1)
- Gamma rate variation.
- PAM (DCMut), PMB, and the Categories model.
- Resolving protein ambiguity codes in the likelihood.
- `protpars` (parsimony).
- Sequence alignment.
- Bootstrap/consensus (v1.2).
- A pair panel for DNA.
- Changing any DNA behavior.

## 3. Engine (`neophylo-core`)

### 3.1 Alphabet
- `pub enum Alphabet { Dna, Protein }`. `Alignment` gains `pub alphabet: Alphabet`, with serde default `Dna`, so v1
  data deserializes unchanged.
- **Protein state order** (fixed, the order of the published JTT data): `ARNDCQEGHILKMFPSTWYV` = indices 0–19.
- **Accepted protein characters**, case-insensitive: the 20 above, plus `B Z J X U O * - ?`. All of the non-standard
  ones are **missing**, i.e. pairwise-deleted for every model.
  - Documented difference: `protdist` partly resolves B/Z in its likelihood. Parity fixtures therefore contain
    no ambiguity codes.
- **Auto-detection** (`detect_alphabet`), ignoring `-` and `?`:
  - Protein if any character is in `E F I L P Q J O Z X *`.
  - Otherwise DNA if at least 90% of characters are in `A C G T U N`.
  - Otherwise protein.
- **Override:** `with_alphabet(aln, Alphabet) -> Result<Alignment, NeoError>` re-validates characters for the
  chosen alphabet (`UnsupportedCharacter` on failure).
- DNA validation and U→T handling are unchanged (v1 §4.1). In protein mode, `U` is selenocysteine (missing),
  not uracil.

### 3.2 PHYLIP format (`phylip.rs`)
- `pub enum NameMode { Strict, Relaxed, Auto }`.
  `pub fn parse_phylip(text: &str, names: NameMode) -> Result<(Alignment, NameMode /*used*/), NeoError>`.
- **Header:** first non-empty line `n m` (whitespace-separated), with optional trailing option letters ignored.
  - Sequences must total exactly `m` characters (internal spaces ignored).
  - Count mismatches give `Parse { line, col, msg }` naming the taxon and the counts.
- **Layout:** auto-detected sequential vs interleaved. Interleaved means the first block has `n` lines, followed by
  continuation blocks without names, separated by optional blank lines.
- **Names:**
  - `Strict`: the first 10 characters of each first-block line, trimmed of trailing spaces. Internal spaces are allowed.
  - `Relaxed`: the name runs up to the first whitespace.
  - `Auto`: Relaxed if that parse is consistent with `n` and `m`; otherwise Strict. The mode actually used is returned
    so the UI can show it.
- **CRLF, a BOM and blank lines** are tolerated, as in FASTA (v1 Review Focus 1). Duplicate names give `Parse`.
- The alphabet is detected per §3.1 after parsing.
- `pub fn write_phylip_matrix(m: &DistanceMatrix, names: NameMode) -> Result<String, NeoError>`:
  - Output is `neighbor` input format: the first line is `n`; each row is the name (padded to 10 characters in Strict,
    or followed by one space in Relaxed) and then the distances with 6 decimals.
  - Strict mode with any name longer than 10 characters gives `InvalidExercise { field: "names", msg }`, so the UI
    can offer Relaxed or truncation.
  - Saturated cells are written as `-1.000000`, PHYLIP's convention, with a UI warning.

### 3.3 Substitution models (`model.rs`, `model/jtt_constants.rs`)
- `pub struct RateModel { pub name: &'static str, pub n: usize, pub freqs: [f64; 20], eigvals: [f64; 20],
  u: [[f64; 20]; 20], u_inv: [[f64; 20]; 20] }`.
  `pub fn transition_probs(&self, t: f64) -> [[f64; 20]; 20]` computes `U · diag(exp(λ t)) · U⁻¹` with `libm::exp`,
  clamping each entry to at least `1e-300`.
- **Scaling:** Q is normalized so `−Σ πᵢ qᵢᵢ = 1`, i.e. distances are in expected substitutions per site, `protdist`'s
  units (1.0 = 100 PAM).
- **Constants are generated, never hand-typed:**
  - `scripts/gen_models.py` (numpy) reads `data/models/jtt.dat`: the published JTT (1992) exchangeabilities and
    frequencies. Its source and SHA-256 are recorded in `data/models/README.md`.
  - The script builds the reversible Q and diagonalizes the symmetric form `Π^½ Q Π^-½`, then writes
    `jtt_constants.rs` with 17 significant digits.
  - The generated file carries a header naming the script and input checksum. A test fails if the checksum differs.
  - Constants are derived from the published data, not copied from PHYLIP source, so no PHYLIP code license applies.
- **`pub static JTT: RateModel`.**

### 3.4 Protein distances (`dist.rs` extension)
- `DistModel` gains `Kimura` and `Jtt`. `P` serves both alphabets.
- **Model/alphabet compatibility:**
  - DNA: P, Jc69, K80.
  - Protein: P, Kimura, Jtt.
  - Anything else gives a new `NeoError::ModelAlphabetMismatch { model, alphabet }`.
- **Comparable sites:** a site counts for a pair only when both characters are standard states, otherwise
  `InsufficientOverlap` (as in v1).
- **Kimura:** p = differences / comparable sites; `x = 1 − p − 0.2p²`; `Saturated` if `x ≤ 0` (p ≥ ≈0.854);
  otherwise `d = −ln x` (`libm::log`).
- **JTT:**
  - Count a 20×20 pair table N once per pair.
  - `logL(d) = Σ N_xy · ln(π_x · P_xy(d))`.
  - Maximize on [0, 10] by Brent's method to an absolute tolerance of 1e-10 in d.
  - `d̂ = 0` exactly when the sequences are identical over comparable sites.
  - `Saturated` if the maximum lies within 1e-6 of 10 (`protdist` writes −1.0 here).
- **Detail for teaching:** `pub fn jtt_pair_detail(aln, i, j) -> Result<PairDetail, NeoError>`:
  ```rust
  pub struct PairDetail { pub a: usize, pub b: usize, pub comparable: u32, pub differences: u32,
    pub p: f64, pub kimura: Cell, pub jtt: Cell, pub counts: Vec<(u8, u8, u32)>, // sparse N_xy
    pub curve: Vec<(f64, f64)>, // 60 points of (d, logL) on [0, max(2·d̂, 0.5)], or [0, 10] if saturated
    pub d_hat: Option<f64>, pub logl_hat: Option<f64> }
  ```
  Computed only on demand for one pair.
- **Budget:** a full JTT matrix for 200 taxa × 1,000 sites in under 2 s in the browser (wasm, single-threaded).

### 3.5 JTT simulation (`sim.rs` extension)
- `SimModel` gains `Jtt` (protein).
  - The root draws from `JTT.freqs` by cumulative comparison in state order.
  - Each branch draws one uniform per site and samples from `P(t)[x]` cumulatively in state order.
  - **RNG consumption order exactly as v1 §4.2.**
- DNA `SimModel` paths are untouched. **The three existing golden hashes must not change.** Add a JTT golden.

### 3.6 Exercises, schema v2
```json
{ "schema_version": 2, "id": "...", "title": "...", "alphabet": "dna" | "protein",
  "data": { "kind": "simulated", "true_tree": "<newick>", "sim": { "model": "JC69"|"K80"|"JTT", "kappa"?: 2, "length": 1000, "seed": 42 } }
        | { "kind": "embedded", "fasta": "<aligned FASTA>", "source": { "citation": "...", "license": "CC BY 4.0", "accessions": ["..."] } },
  "reference": { "newick": "<newick>", "kind": "true" | "classification" } | null,
  "analysis": { "correction": "p"|"JC69"|"K80"|"Kimura"|"JTT", "method": "NJ"|"UPGMA" },
  "locked": [...], "prompts": [...] }
```
- **Migration from v1:** `data.kind = "simulated"` from the v1 `true_tree` and `sim`; `reference = { newick: true_tree,
  kind: "true" }`; `alphabet = "dna"`. It applies to exercise files and to URL state (v1 §6.4).
- **Validation:**
  - `alphabet` must match `sim.model` and `analysis.correction` (`ModelAlphabetMismatch`).
  - Embedded FASTA must parse and match `alphabet`.
  - A reference tree's labels must match the alignment (`LabelMismatch`).

### 3.7 Errors
- New: `ModelAlphabetMismatch { model: String, alphabet: Alphabet }`.
- Reused: PHYLIP format errors use `Parse { line, col, msg }`.
- The engine must not panic on any input (v1 §4.7). `parse_phylip` gets a fuzz target with seeds.

## 4. wasm boundary

- `detect_alphabet(alignment)`.

## 5. Web app

### 5.1 Controls and import
- **Alphabet badge:** "DNA" or "Protein · 20 amino acids", with an override control (the "Treat as protein/DNA"
  action calls `with_alphabet`).
- **Model menus filtered by alphabet:**
  - correction: DNA p/JC69/K80; protein p/Kimura/JTT (**default JTT**)
  - simulation: JC69/K80 or JTT
- **Import** accepts FASTA or PHYLIP (`.phy`, `.phylip`, `.txt`, extensionless such as `infile`) and auto-detects the
  format. Input whose first non-blank line matches `^\s*\d+\s+\d+` is PHYLIP.
  - When PHYLIP Auto chose a mode, a "Strict / Relaxed names" toggle shows the mode used, with a one-line explanation.
- **Session additions:** `reference: { tree, kind } | null` replaces `trueTree`; `alphabet`. The v1 `trueTreeOrigin`
  rules apply to `reference`.

### 5.2 Pair panel: "How was this distance computed?"
In protein mode, when no predict prompt is active, activating a matrix cell (click or Enter) opens the panel for that
pair (from `jtt_pair_detail`):
- **The two sequences aligned,** comparable differing sites marked with a symbol row (not color alone), and missing
  sites dimmed. Amino-acid coloring by property class uses a palette checked for colorblind safety.
- **p, Kimura and JTT side by side,** with Saturated shown as "can't estimate".
- **Likelihood curve (SVG):** logL vs d, with the peak marked at d̂ (or "no peak: still rising" when saturated).
  - **Concept:** "JTT picks the distance that makes these two sequences most probable, given how often each amino acid
    is replaced by each other."
  - **Math:** `logL(d) = Σ N_xy ln(π_x P_xy(d))`, the number of comparable sites, and d̂ to 3 decimals (the v1
    precision rule).
- Accessible: `role="dialog"`, focus trapped while open, Esc closes; the curve has an `aria-label` stating d̂.

### 5.3 Reference trees
The tree panel title follows `reference.kind`:
- "True tree" for simulated data.
- **"Reference (accepted classification), not a known true tree"** for classification.

RF text for a classification reference reads "differs from the accepted classification in N clade(s)".

### 5.4 Lessons
- **`protein-models` (simulated, JTT, NJ):** 6–8 taxa; a true tree with one fast-evolving lineage.
  - The premise is asserted in e2e at the chosen seed: p-distance gives RF > 0, and JTT gives RF = 0.
  - A predict prompt, whose reveal invites opening the pair panel for the misleading pair.
  - A closing note on why counting differences underestimates long distances.
- **`cytochrome-c` (embedded real data, JTT, NJ):** about 8 species spanning mammals, a bird, a fish and yeast.
  - The alignment is produced offline (any standard aligner, recorded in `source`), committed as aligned FASTA,
    with UniProt accessions and the CC BY 4.0 attribution shown in the lesson.
  - The species, accessions and classification Newick are chosen during implementation and **verified by the owner**.
  - The reference kind is `classification`, and the closing note discusses agreement and disagreement.
- The v1 lesson conventions apply (at_step, no placeholders, no predict on NJ's final join).

### 5.5 "Coming from PHYLIP?" help panel
Reachable from the header. It maps:
- `protdist` defaults → JTT; `dnadist` → see the K80 note (v1 §8.1).
- `neighbor` defaults → NJ.
- `infile` loads directly (PHYLIP import).
- "Export → Distance matrix (PHYLIP)" produces a file `neighbor` reads.
- No `outfile`/`infile` renaming needed.

### 5.6 Export additions
- **Distance matrix (PHYLIP),** via `write_phylip_matrix`; Strict by default, falling back to Relaxed with a note when
  names are too long.
- **R script for protein:**
  - p: `ape::dist.aa(..., pairwise.deletion = TRUE, scaled = TRUE)`.
  - Kimura: computed explicitly as `-log(1 - p - 0.2*p^2)` from that proportion.
  - JTT: `phangorn::dist.ml(phyDat(..., type = "AA"), model = "JTT")`, with a comment stating the measured agreement
    with NeoPhylo (§6.3).

## 6. Validation

### 6.1 Fixtures (human gate, as v1 Task 2)
- **`fixtures/worked/protdist_doc_jtt.json`:** the 5-sequence test data from PHYLIP's `protdist` documentation,
  read as **protein**, with its published JTT matrix (6 decimals), hand-entered and **verified by the owner** against
  the documentation page.
- **`fixtures/generate_phylip.sh`** gains a protein path: 4 protein alignments (6–12 taxa, 100–400 sites, no ambiguity
  codes, no tied minimum joins), run through `protdist` (JTT, then Kimura; all other settings default), then
  `neighbor` (NJ). Output is parsed to JSON with `precision` = printed decimals.
- **`fixtures/generate.R`** gains `phangorn::dist.ml(model = "JTT")` and `ape::dist.aa` outputs for the same inputs,
  marked `oracle: "second_opinion"`.

### 6.2 Engine tests
- **Model:**
  - Q rebuilt from the stored constants has rows summing to 0 (1e-12) and satisfies `π_i q_ij = π_j q_ji`.
  - `P(0) = I`, and P(t) rows sum to 1 (1e-12) for t ∈ {0.01, 0.1, 1, 5}.
  - The constants file checksum matches the script input.
- **JTT fit:**
  - Identical sequences give d̂ = 0.
  - |d logL/dd| at d̂ is below 1e-6 (numerical derivative).
  - On simulated data, JTT is closer to the true path length than p in aggregate (sanity test over 20 seeded
    pairs at lengths ≥ 0.5). Not asserted per pair: an ML estimate is not guaranteed to exceed p for every pair.
  - The curve has a single peak over sampled points (property test on random pairs).
- **Parity:**
  - `protdist_doc_jtt` matches to 5e-7.
  - The `protdist` fixtures match to `0.5·10^-precision`, or, if a systematic JTT difference appears, **stop and
    investigate the constants. Never loosen the tolerance.** Any accepted residual needs owner sign-off in
    `decisions.md`.
  - Kimura matches its formula exactly and `protdist` to printed precision.
  - NJ trees built from `protdist` matrices: RF = 0 and branch lengths within tolerance (v1 §8.1 method).
- **Second opinion:** the maximum |NeoPhylo − phangorn| JTT difference is measured and recorded in `decisions.md`.
  Not a gate.
- **Convergence:** JTT simulation with 100,000 sites at branch length 0.3, seed fixed, gives a JTT estimate within 2%.
  The root composition matches JTT frequencies within 0.01 per state.
- **Golden:** the three v1 DNA hashes are unchanged; a new JTT golden is added (`regen_golden` stays the only
  ignored test).
- **Alphabet:**
  - Detection cases (DNA, protein, DNA-looking protein).
  - The **PHYLIP documentation data auto-detects as DNA**; after `with_alphabet(Protein)` it reproduces the published
    JTT matrix (this checks the override end to end).
- **PHYLIP parser:**
  - Strict names with internal spaces; relaxed names.
  - Sequential and interleaved, with and without blank lines between blocks.
  - Header count mismatches (exact error line); CRLF/BOM; duplicate names.
  - Auto choosing each mode.
  - Round-trip of `write_phylip_matrix` through `neighbor` in the fixture script.
- **Migration:** every v1 lesson and a corpus of v1 URL states produce an identical step-0 matrix after migration to v2.
- **Fuzz:** `parse_phylip` target with seeds (fixture inputs plus PHYLIP doc data).

### 6.3 Web and end-to-end
- Model menus filter correctly by alphabet; `ModelAlphabetMismatch` shows "JC69 is for DNA; this data is protein.
  Choose p, Kimura or JTT."
- The pair panel's numbers equal the engine output; a saturated pair shows "no peak".
- Accessibility: dialog behavior, axe scan.
- e2e for both lessons, including their asserted premises; v1 lessons unchanged.
- R export parity extended to protein (p and Kimura to 1e-9; JTT to the measured second-opinion tolerance).
- Performance: an e2e timing check that a 200×1,000 protein JTT matrix renders in under 2 s on CI (coarse).

## 7. Risks
| Risk | Mitigation |
|---|---|
| `protdist`'s JTT data or scaling differs from the published JTT | The documentation test output is the first gate; on mismatch, investigate constants and scaling before anything else. |
| The ML search lands on a wrong optimum | logL(d) is unimodal for a pair under a reversible model; Brent on a bounded interval; slope-at-d̂ property test. |
| Auto-detection misclassifies | The detected alphabet is always shown; one-click override; DNA-looking protein test. |
| Students read the classification as "the truth" | Explicit reference labeling; lesson closing note. |
| Breaking v1 links | DNA paths untouched; golden hashes; migration corpus test. |
