# NeoPhylo v1.2: Bootstrap, consensus and reference rooting, design spec

Status: Draft for review · Date: 2026-10-19 · Repo path: `docs/superpowers/specs/2026-10-19-neophylo-v1.2-bootstrap-design.md`
Builds on the v1 spec ("v1 §") and the v1.1 spec ("v1.1 §").

## 1. Purpose and decision record

v1.2 completes the most common PHYLIP teaching lab, `seqboot` → `dnadist`/`protdist` → `neighbor` →
`consense`, and answers the question students ask once they have a tree: **how sure are we?**
It also fixes the display problem found with the cytochrome c lesson: an NJ tree must be drawable
**rooted like the reference** so the two pictures can be compared.

**Decisions (owner, brainstorming 2026-10-19):**
- **Consensus types:** majority rule, extended majority rule (`consense`'s default) and strict.
- **Main view:** support values on the **original** tree, with consensus trees one click away.
- **Heavy runs:** a single background Web Worker with progress and cancel. Multi-core is rejected: it
  needs cross-origin isolation headers, which would block iframe embedding (roadmap v1.5).
- **Architecture:** the Rust engine owns all science (resampling, distances, trees, tallies,
  consensus, support, rerooting). The worker runs it in batches. Nothing scientific is computed in
  TypeScript.
- **Rerooting:** automatic for NJ trees at the final step when a reference exists, with a
  "Show as computed (unrooted)" toggle.

**Validation stance:** `seqboot`'s random numbers can't be reproduced, so bootstrap *values* are
validated statistically against R. **Consensus and support counting are validated exactly**,
because `consense` and `ape::prop.clades` are deterministic on a fixed set of trees.

## 2. Scope

### 2.1 In v1.2
- Nonparametric bootstrap (column resampling) for NJ and UPGMA on every v1/v1.1 distance model,
  DNA and protein.
- Support values on the original tree.
- Consensus trees: strict, majority, extended majority.
- "Watch one replicate" resampling view.
- Background worker with progress, ETA, cancel and live support updates.
- Display-only rerooting on the reference outgroup.
- A `predict_branch` prompt type and a `bootstrap-basics` lesson.
- Exports: Newick with support, consensus Newick, SVG/PNG with support labels, R script with
  `boot.phylo`.

### 2.2 Non-goals
- Jackknife, transfer bootstrap (TBE), parametric bootstrap.
- Multi-core computation.
- Storing bootstrap results in links (links store settings; results are recomputed).
- Bootstrap for imported Newick trees without sequences.
- User-chosen outgroups (roadmap v1.7).
- Any change to DNA/protein distance values, simulation, or existing lesson results.

## 3. Engine (`neophylo-core`)

### 3.1 Weighted distances
- `compute_weighted(aln: &Alignment, model: DistModel, w: &[u32]) -> Result<DistanceMatrix, NeoError>`.
  `w.len()` equals the number of alignment columns.
- A column with weight k counts k times in comparable sites, differences, and (JTT) pair counts.
- **Identity rule:** all-ones weights reproduce `compute(aln, model)` **bit for bit**.
- **Equivalence rule:** `compute_weighted(aln, m, w)` equals `compute(aln', m)`, where `aln'` repeats
  column j exactly `w[j]` times (in column order).
- Weight 0 drops a column. A pair with zero weighted comparable sites gives `InsufficientOverlap`.

### 3.2 Resampling
- Replicate *i* (0-based) uses `ChaCha8Rng::seed_from_u64(seed)` followed by `set_stream(i as u64)`.
- It draws L column indices (L = number of columns). Each index is
  `((rng.next_u64() as u128 * L as u128) >> 64) as usize`, incrementing `w[index]`.
- Draws come in that order, and nothing else consumes the stream.
- **Consequence:** the same seed and *i* always give the same replicate, independent of batching,
  ordering or cancellation.

### 3.3 Groupings and tallies
- `Split` is a fixed-width bitset over taxon indices (alignment order), with 4 × u64 words for ≤ 200 taxa.
- **NJ (unrooted):** each non-trivial split (both sides ≥ 2 taxa) is canonicalized as the side **not**
  containing taxon 0.
- **UPGMA (rooted):** each cluster is the leaf set of a non-root internal node, with 2 ≤ size ≤ n−1.
- `BootstrapTally { method, n, successful: u32, failed: u32, counts: BTreeMap<Split, u32> }`.
- `merge(a, b)` adds the counts. Ordered maps give deterministic iteration.
- A replicate whose weighted matrix has any `Saturated` cell, or a pair with no comparable sites
  (possible when resampling drops every shared column), is **not built**; it increments `failed`.
  Other errors propagate.
- `bootstrap_batch(aln, model, method, seed, start: u32, count: u32) -> Result<BootstrapTally, NeoError>`
  covers replicates `start .. start+count`, and trees are discarded after tallying.
- If every requested replicate fails, the result is the new error
  `NeoError::BootstrapFailed { failed, total }`.

### 3.4 Support on the original tree
- `support_on_tree(tree: &Tree, tally: &BootstrapTally) -> Tree` sets `BranchAttrs.support: Option<f64>`
  (new field, fraction 0–1) on every internal branch whose split or cluster is in scope:
  - `count / successful`, or `0.0` if absent from the tally.
  - Terminal branches get `None`.
- Support is a **branch** attribute (v1 §4.4), so it follows its grouping under rerooting.

### 3.5 Consensus
`consensus(tally: &BootstrapTally, kind: ConsensusKind, labels: &[String]) -> Tree`, with
`ConsensusKind = Strict | Majority | Extended`.
- **Strict:** groupings with `count == successful`.
- **Majority:** groupings with `count > successful / 2` (strictly greater).
- **Extended:** start from Majority. Consider the remaining groupings in order of decreasing count, ties
  broken by ascending bitset value (lowest taxon indices first). Add each grouping that is compatible
  with all accepted ones; stop when no candidates remain or the tree is fully resolved.
- The tree is built from the accepted groupings: unrooted (NJ) or rooted (UPGMA). It has no branch
  lengths. Each internal branch carries `support = count / successful`.
- `consensus_dropped(tree, tally, kind) -> Vec<(Split, f64)>`: groupings of the original tree that are
  absent from the consensus, with their support (shown in the UI).

### 3.6 Replicate detail (teaching)
`replicate_detail(aln, model, method, seed, i) -> Result<ReplicateDetail, NeoError>`:
`{ weights: Vec<u32>, undrawn: u32, tree: Option<Tree>, failed: bool, rf_to_original: Option<u32>,
differing: Vec<Split> }`. Computed on demand for one replicate.

### 3.7 Rerooting for display
`reroot_on_outgroup(tree: &Tree, outgroup: &[String]) -> Result<RerootResult, NeoError>`.
- **Outgroup from a reference:** the leaf set of the reference root's child subtree with fewer leaves
  (on a tie, the child containing the alphabetically first label).
- **If the outgroup set is a split of the tree:** the root is placed at the midpoint of that branch,
  and the two new edges each get half its length.
  - The split's support is placed on the **ingroup-side** edge only; the outgroup-side edge gets
    `None`, so the value is never shown twice.
  - All other branches keep their length and support attached to the same grouping.
- **Otherwise:** the root goes at the midpoint of the terminal branch of the alphabetically first
  outgroup taxon, with `outgroup_is_group: false`.
- `RerootResult { tree, outgroup_is_group: bool }`. Display-only: the computed tree is never replaced.
- UPGMA trees are already rooted and are not rerooted.

### 3.8 Errors and limits
- New error: `BootstrapFailed { failed, total }`.
- Replicates: 10–1,000 (the UI clamps; exercise files outside the range give
  `InvalidExercise { field: "bootstrap.replicates" }`). The 200-taxon limit applies.
- The engine never panics (v1 §4.7). `bootstrap_batch` and `reroot_on_outgroup` get fuzz coverage via
  the exercise target.

## 4. wasm boundary
New exports, each returning `WasmResult` (v1 §5):
- `bootstrap_batch(aln, model, method, seed, start, count)`
- `merge_tallies(a, b)`
- `support_on_tree(tree, tally)`
- `consensus(tally, kind, labels)`
- `consensus_dropped(tree, tally, kind)`
- `replicate_detail(aln, model, method, seed, i)`
- `reroot_on_outgroup(tree, outgroup)`

`Split` serializes as a sorted label list for display. Types are generated; no `bigint` (counts are u32).

## 5. Background worker (`web/src/engine/worker.ts`)

Loads the same wasm package and runs only bootstrap jobs. Everything else stays on the main thread.

| From | Message | Fields |
|---|---|---|
| page | `start` | jobId, alignment, model, method, seed, replicates |
| worker | `estimate` | jobId, msPerReplicate, totalMs (sent after replicate 0) |
| page | `confirm` / `cancel` | jobId |
| worker | `progress` | jobId, done, total, failed, etaMs, support (support_on_tree of the running tally) |
| worker | `result` | jobId, tally, support tree, consensus ×3, dropped ×3, failed |
| worker | `error` | jobId, NeoError |

**Run sequence:**
1. The worker runs replicate 0 alone and sends `estimate`.
2. If `totalMs > 10,000`, the page shows "This will take about N" with Start and Cancel, and the
   worker waits for `confirm`. Otherwise the page confirms immediately.
3. The worker then runs batches sized to about 100 ms each, based on `msPerReplicate`, sending
   `progress` after each batch.

**Cancel:**
- Cancel is checked between batches.
- If the worker doesn't acknowledge within 1 s, the page terminates it and spawns a fresh worker.

**Stale results:** messages whose jobId isn't current are ignored. Changing alignment, model or method
cancels the current job.

**Offline:** the worker chunk is precached by the service worker.

## 6. Web app

### 6.1 Session and URL
- **`Session.bootstrap`:**
  `{ status: "idle"|"estimating"|"confirming"|"running"|"done"|"cancelled"|"error", replicates, seed,
  done, total, failed, etaMs, support: Tree|null, consensus: {...}|null, dropped, view: "support"|
  "majority"|"extended"|"strict", replicateIndex: number|null }`.
  - Defaults: 100 replicates, seed 1, view "support".
  - Any change to alignment, model, method or data clears results (status → "idle").
- **URL v3:** adds `bootstrap: { replicates, seed, view, ran: boolean }`. v2 links migrate to defaults
  with `ran: false`.
  - On open with `ran: true`, a run starts automatically if replicate 0 estimates `totalMs ≤ 10,000`.
  - Otherwise a prefilled "Run bootstrap (N replicates)" button is shown.
  - Results are never stored in links.

### 6.2 "How sure are we?" panel
- Appears under Analysis when the stepper is at its final position.
- Replicates input (10–1,000), seed, Run/Cancel.
- A `progressbar`: "Replicate k of N · about T left", and "F replicates skipped (saturated)" when F > 0.
- **Warnings:**
  - More than 10% skipped: "The data is close to saturation; support is based on fewer replicates."
  - `BootstrapFailed` uses the friendly error mechanism, suggesting p-distance or longer sequences.

### 6.3 Support on the tree
- Each internal branch shows its support as an integer percentage label (`Math.round(100·s)`).
- Below 50%: a thinner line plus a "weak" marker glyph (never color alone).
- Labels update live from `progress` messages.

### 6.4 Consensus views
- Tabs above the inferred tree: "Your tree with support" | "Majority-rule" | "Extended majority" | "Strict".
- Consensus views draw the consensus tree, with no lengths (cladogram), and support labels.
- A list "Dropped from this consensus: (C, D) 42%, …" from `consensus_dropped`.

### 6.5 Watch one replicate
- A panel opened from "How sure are we?" for replicate 1, 2, 3…, with Previous/Next buttons:
  - a column strip with each column's draw count (0 dimmed)
  - "U of L columns not drawn (≈ 37% expected)"
  - the replicate tree beside the original, with differing groupings outlined
  - "This replicate was skipped (saturated)" when `failed`
- Uses `replicate_detail`; computed on the main thread (a single replicate is fast). For large
  protein data (estimated > 2 s) it runs in the worker as a one-replicate job instead.

### 6.6 Explanations
- **Concept:** "87 means this group appeared in 87 of 100 resampled datasets. It measures how
  consistently the data supports the group, not the probability that the group is true."
- **Math:** `support = count / successful replicates`; columns are drawn with replacement, and the
  chance a given column is never drawn is (1 − 1/L)^L ≈ e⁻¹ ≈ 36.8%.

### 6.7 Rerooting display
- At the final step, when a reference exists and the method is NJ, the inferred tree is drawn from
  `reroot_on_outgroup` with the reference's outgroup, by default.
- Toggle: "Show as computed (unrooted)".
- **Caption, rerooted:** "Drawn with the same outgroup as the reference; rerooting changes only the
  drawing, not the groupings."
- **Caption, computed:** the v1.1 unrooted caption.
- If `outgroup_is_group` is false: "The reference's outgroup isn't a single group in this tree; rooted
  next to <taxon>."

### 6.8 Exports
- **Newick:** support as internal node labels (integer %), the convention read by FigTree, iTOL and ape.
- **"Consensus (Newick)":** the current consensus view.
- **SVG/PNG:** include support labels.
- **R script:** adds `boot.phylo(tree, x, function(xx) <same distance + method>, B = <replicates>)` and
  `plotBS`/`nodelabels`, with a comment: "R's random draws differ from NeoPhylo's; support values vary
  by a few percent."

## 7. Lesson and prompt type

### 7.1 `predict_branch`
- A new optional prompt type (exercise schema v2, additive): `{ "type": "predict_branch",
  "at": "bootstrap", "concept", "math" }`.
- It appears when the "How sure are we?" panel first shows; Run is disabled until the student clicks
  an internal branch of the inferred tree.
- After the run, the verdict compares the clicked branch with the lowest-support branch ("Correct" /
  "Not quite: the weakest group was (C, D) at 41%"), with explanation.
- Exercise files may include `bootstrap: { replicates, seed }` (validated).

### 7.2 `bootstrap-basics` ("How sure are we?")
- Simulated DNA (JC69), 8 taxa, NJ. All internal branches ≥ 0.05, except one of 0.005.
- Length 300; replicates 100; the bootstrap seed is found by search.
- **Premises, asserted end to end at the chosen seeds:**
  - the lowest support is on the designed short-branch grouping, and below 70%
  - at length 3,000 (the lesson's lever), that grouping's support rises by at least 20 points
- Prompts: `predict_branch`, then a note inviting the length change. The closing note addresses the
  "probability it's true" misreading.
- v1 lesson conventions apply (no placeholders, etc.).

## 8. Validation

### 8.1 Fixtures (owner gate)
- **`fixtures/consensus/`:** R-generated tree sets (`ape::rtree` / `rmtree`, seeded; 6–12 taxa;
  20–200 trees, including tree sets built from real bootstrap replicates of fixture alignments), each
  run through PHYLIP `consense` for strict, majority and extended majority. Unrooted sets cover NJ;
  rooted sets (`consense` option R) cover UPGMA clusters. Recorded:
  - the consensus topology and per-grouping counts
  - `ape::prop.clades` counts of each tree set against a reference tree

  The generator asserts no ties at any extended-majority decision; the owner verifies one small
  hand-built example (5 taxa, 10 trees).
- Generated by `fixtures/generate.R` and `fixtures/generate_phylip.sh`; CI regenerates and diffs, as
  before.

### 8.2 Engine tests
- **Weighted distances:** the identity rule (bit for bit) for every model; the equivalence rule as a
  property test (random alignments and weights, DNA and protein).
- **Resampling:**
  - determinism
  - **batch independence:** tallies for 100 replicates as 1×100, 4×25, 100×1 and a cancelled
    (60 + 40) run are identical
  - the mean fraction of undrawn columns over 2,000 replicates of L = 500 is within 0.368 ± 0.01
- **Counting:** support counts on fixture tree sets equal `prop.clades` exactly.
- **Consensus:** strict, majority and extended trees and counts equal `consense` exactly (RF = 0, counts
  equal).
- **Reroot (property):** random trees with random support, rerooted on a random outgroup:
  - every grouping keeps its support exactly (shown once)
  - total tree length is unchanged
  - groupings are unchanged as an unrooted set

  Plus the non-group outgroup case.
- **Failure handling:** a near-saturated alignment produces skipped replicates and the correct counts;
  an all-failed run gives `BootstrapFailed`.

### 8.3 R statistical parity (CI `r-and-fixtures`)
For two fixture alignments (one DNA JC69, one protein Kimura), 1,000 replicates: every branch's
NeoPhylo support is within **5 percentage points** of `ape::boot.phylo` (B = 1,000) with the same
distance and method.

### 8.4 Web and end-to-end
- **Worker:**
  - its result equals direct engine calls with the same seed
  - progress is monotone
  - cancel completes in ≤ 1 s
  - a stale result is ignored
  - the confirm flow appears above 10 s (forced via a test hook)
- **UI:** support labels and weak markers; consensus tabs and the dropped list; the replicate panel;
  rerooted drawing plus toggle; `predict_branch` gating and verdict; URL v3 migration (v2 corpus
  unchanged); offline worker.
- **Lesson premises:** `bootstrap-basics` asserts its premises; all v1/v1.1 lessons are unchanged.
- **Accessibility:** `progressbar` semantics, a completion announcement, keyboard operation of tabs and
  the replicate panel, axe clean.

### 8.5 Performance
- Lesson-sized data (≤ 10 taxa, ≤ 1,000 sites): 1,000 replicates in under 1 s (Chromium, CI).
- 200 × 1,000 protein JTT, 100 replicates: the ETA after replicate 0 is within 30% of the actual
  time; no main-thread task over 50 ms during the run (Long Tasks API check in e2e).

## 9. Risks
| Risk | Mitigation |
|---|---|
| Extended-majority tie handling differs from `consense` | Fixed tie rule (§3.5); fixtures avoid ties; any divergence goes to the owner |
| Support misplaced after rerooting | §3.7 rule plus the reroot property test |
| Students read support as probability | §6.6 Concept text, plus the lesson's closing note |
| Long runs feel broken | Estimate, confirm, progress, ETA, cancel |
| Worker and main thread diverge | Results compared against direct engine calls in tests |
