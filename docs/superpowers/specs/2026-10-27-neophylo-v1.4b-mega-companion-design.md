# NeoPhylo v1.4b: MEGA companion and data library, design spec

Status: Draft for owner review · Date: 2026-10-27 · Repo path: `docs/superpowers/specs/2026-10-27-neophylo-v1.4b-mega-companion-design.md`
Builds on the v1, v1.1, v1.2, v1.3 and v1.4 specs. Roadmap entry: `docs/roadmap.md` § v1.4b (narrowed by this spec; the remainder moves to a new **v1.4c**).

## 1. Purpose and decision record

v1.4b makes NeoPhylo a companion for MEGA labs: a student understands a step in NeoPhylo, then reproduces it in MEGA and gets the same numbers. It adds MEGA's gap treatments and protein distances to the engine, reads and writes `.meg` files, validates against MEGA's command-line version, and ships a small library of real, openly licensed datasets.

**Decisions (owner, brainstorming 2026-10-27):**
- **Split:** v1.4b = MEGA companion (handouts, "Coming from MEGA?", `.meg` import and export, MEGA-CC oracle) + curated data library as bundled offline datasets + the sandbox model menu. **v1.4c** = fetch by UniProt/NCBI accession, distance-matrix import (`.meg` and PHYLIP), the lesson library page, printable worksheets with answer keys, and the instructor guide.
- **MEGA-CC oracle runs locally.** MEGA is closed-source and is not put in a CI image. `fixtures/generate_mega.sh` runs a locally installed MEGA-CC with committed `.mao` settings files; its outputs are committed and frozen, with the MEGA version recorded. CI checks against them and never regenerates them.
- **Gap treatment: all three of MEGA's options.** Pairwise deletion (the current behavior, still the default), complete deletion, and partial deletion with a site-coverage cutoff.
- **Full protein parity with MEGA:** p-distance, Poisson (a new model) and JTT. If MEGA's JTT differs from `protdist`'s, it becomes a separately named model (§3.3).
- **Library datasets are rebuilt from public accessions** by a committed script at build time, with size caps and provenance. The browser never fetches sequence data.
- **`.meg`:** sequence import and export in v1.4b. Distance-matrix `.meg` files are refused with a message pointing to v1.4c.
- **Gap treatment is a site filter producing column weights** (approach A, §3.1), fed into the existing weighted distance path. No distance function changes.

**Success criteria:**
1. Every distance model and gap treatment in §3 matches MEGA-CC's printed output on committed fixtures, and NJ and UPGMA trees match MEGA-CC's.
2. Bootstrap support matches MEGA-CC within sampling noise on the handout datasets.
3. Every MEGA handout reproduces MEGA's numbers with the settings it lists.
4. A `.meg` file exported by NeoPhylo opens in MEGA-CC and gives the same distances; every `.meg` fixture round-trips through NeoPhylo's writer and parser unchanged.
5. Each library dataset loads in one click, shows its source and license, and stays within the size caps (§5.2).
6. All existing engine, parity, lesson-premise and old-link tests pass unmodified. No existing number changes.

## 2. Scope

### 2.1 In v1.4b
- Engine: `SiteFilter` (pairwise, complete, partial), the `Poisson` protein model, `JTT_MEGA` if needed (§3.3), the `.meg` parser and writer.
- MEGA-CC oracle: generator script, `.mao` files, fixtures, parity tests.
- Data library: five datasets, a build script, provenance files, an "Open dataset" sheet.
- Sandbox: `F84`, `K2P_PHYLIP` (with κ), `Poisson`, `JTT_MEGA` if it exists, and a gap-treatment control. Removed columns shown in the pair panel's site grid, with a count.
- Exercise format: new models and an optional site filter (`schema_version` 4); the editor offers them.
- MEGA companion: four handouts in the lab-pack format and a "Coming from MEGA?" guide; the lab index lists both PHYLIP and MEGA labs.
- Tests for every new model, filter, parser, screen and handout.

### 2.2 Non-goals
- Everything moved to v1.4c (§1).
- Reading MEGA `.mao` files in the app, or reproducing MEGA's bootstrap replicates.
- Gamma-distributed rates, heterogeneous patterns, Tamura-Nei, LogDet, likelihood (v1.7 and later).
- Changes to built-in lessons. They keep their models and pairwise deletion.
- Any change to existing distances, trees, bootstrap, simulation or lesson results.

## 3. Engine

All new code is in `crates/neophylo-core`, pure Rust, uses `libm` for all math, follows the determinism rules in `docs/architecture.md`, and never panics on any input.

### 3.1 Site filter
- `SiteFilter { Pairwise, Complete, Partial { cutoff_pct } }` turns an alignment into one 0/1 weight per column.
- A sequence is **missing** at a column when its character there is one the engine already pairwise-deletes for that alphabet (`alphabet.rs`: gap, missing, and ambiguity characters).
- **Pairwise:** every column has weight 1. This is exactly today's path; existing callers keep using it by default.
- **Complete:** a column has weight 1 only if no sequence is missing there.
- **Partial { cutoff_pct }:** a column has weight 1 if the percentage of sequences *not* missing there is at least `cutoff_pct` (MEGA's "site coverage cutoff"). `cutoff_pct` is an integer in 0–100; anything else is a `NeoError`. The editor and sandbox default is 95, which the plan confirms against MEGA-CC's default. The comparison at the boundary (≥ vs >) is fixed by a fixture built to sit exactly on it.
- Within kept columns, missing characters are still pairwise-deleted, as in MEGA.
- The weights go into the existing weighted distance path (`dist.rs`, used by bootstrap). No distance function changes, so every model gets all three treatments.
- If the filter keeps no columns, analysis returns a `NeoError` that says so, and the UI shows the message.
- The filter also reports the kept and removed column indices, so the UI can show them (§6.2).

### 3.2 Bootstrap with a filter
The mask is applied before resampling: replicates draw columns only from the kept columns, if MEGA's documentation confirms this is MEGA's behavior. The plan cites the source. If MEGA resamples all columns and filters each replicate, the engine does that instead. Either way, `Pairwise` bootstrap is unchanged, and seeded replicates under `Pairwise` keep their current golden values.

### 3.3 Protein models
- **`Poisson`:** `d = −ln(1 − p)` on pairwise-compared sites. Saturated when `p ≥ 1`, under the existing `Saturated` rules.
- **JTT, fixture-first.** MEGA-CC's JTT distances are generated on the existing protein inputs before any code. If they match `Jtt` at MEGA's printed precision, there is no new model, and the guide says the numbers match MEGA. If they do not, a new model `JTT_MEGA` follows MEGA's estimator; the fixtures are the reference, not a formula in this spec. A test asserts the divergence between `Jtt` and `JTT_MEGA`, as v1.4 does for `K2P_PHYLIP` and `K80`, and the guide explains it.
- Identifier style follows the existing uppercase convention (`JC69`, `K80`, `JTT`, `F84`, `K2P_PHYLIP`): JSON names `POISSON` and, if needed, `JTT_MEGA`. The plan confirms the exact casing against the existing schema enum.

### 3.4 `.meg` I/O
- **Parser** for sequence files: the `#mega` header; `!Title`; `!Format` with `DataType`, `Identical`, `Missing`, `Indel` (case-insensitive keys, any order); sequential and interleaved layouts; `#name` lines; `"…"` comments. The identity symbol is expanded against the first sequence.
- `!Domain`, `!Gene` and `!Label` commands are read and ignored, and the result carries a notice that the UI shows.
- Distance-matrix `.meg` files are recognized and refused with a message that matrix input arrives in v1.4c.
- Malformed input is a `NeoError` with a line number. The parser never panics.
- **Writer:** `#mega`, `!Title`, a `!Format` line with the data type and the gap and missing symbols, sequential layout, full sequences (no identity symbol).
- Writer → parser is the identity on every alignment the engine accepts.

### 3.5 Validation against MEGA
- `fixtures/generate_mega.sh` runs a local MEGA-CC with committed `fixtures/mega/mao/*.mao` files and writes `fixtures/mega/<input>.json`. Each file records the `megacc` version, the sha256 of each `.mao` file, and the printed precision per output.
- Inputs: the existing gap-free and gapped FASTA inputs, the existing protein inputs, the library datasets the handouts use, a boundary fixture for the partial cutoff (§3.1), and `.meg` files exported by NeoPhylo (success criterion 4).
- Outputs per input: distances for p, JC69, K80 (MEGA's "Kimura 2-parameter"), and for protein p, Poisson and JTT, each under pairwise, complete and partial (95) deletion; NJ and UPGMA trees; and for the handout datasets, bootstrap support from 100 replicates.
- Tolerance: half an ulp of MEGA's printed precision, as the PHYLIP parity does. The plan records the precision from the generator's output. No tolerance is loosened to make a test pass.
- Trees are compared two ways: on our own distances, and by feeding MEGA's printed matrix into our NJ and UPGMA, which separates distance differences from tie-breaking differences.
- Bootstrap support is compared within sampling noise, using the same statistical rule as the existing `boot.phylo` comparison.
- Fixture files are committed separately from code (CI's fixture guard). The fixture README documents that MEGA fixtures are frozen and regenerated only locally.
- `.mao` files and MEGA's outputs are our own files; no MEGA binary or MEGA example file is committed.

### 3.6 Property tests
Each is a new `proptest` function, so existing saved seeds stay valid.
- `Complete` equals `Pairwise` on gap-free alignments.
- `Partial { 100 }` equals `Complete`; `Partial { 0 }` equals `Pairwise`.
- Raising the cutoff never keeps a column that a lower cutoff removed.
- `Poisson` is symmetric, has a zero diagonal, is non-negative and is monotone in `p`.
- `.meg` writer → parser is the identity.
- Invalid cutoffs and empty results are `NeoError`s, not panics.
- Fuzz targets cover the `.meg` parser and the new exercise fields.

## 4. Exercise format and state

- `schema_version` goes from 3 to 4. v4 adds the model identifiers from §3.3 and an optional `analysis.site_filter` object: `{ "kind": "pairwise" | "complete" | "partial", "cutoff_pct": <0–100, required for partial> }`. A missing `site_filter` means pairwise. No existing field becomes required, and v1–v3 files load unchanged through the existing migration path.
- New keys get schema-pinning tests for `null` and array values, since serde treats `null` as absent for `Option` fields.
- The exercise editor offers the new models and the site filter. Built-in lessons do not use them.
- URL and link state gain the model and the site filter. The v1.1–v1.4 link corpora restore identically.

## 5. Data library

### 5.1 Datasets
Five datasets: globins (protein), cytochrome c (protein), primate mtDNA (DNA), 16S rRNA (DNA, with gaps, used for the gap-treatment handout material), and a SARS-CoV-2 gene region (DNA, for example the spike gene, not whole genomes). The plan picks the accessions. Where a MEGA handout mirrors a MEGA example file, its dataset is rebuilt from the same public accessions where possible, so students can cross-check; MEGA's example files themselves are not redistributed.

### 5.2 Build and provenance
- `scripts/data/build_library.py` reads a committed accession list per dataset, fetches the sequences from NCBI or UniProt once at build time, and aligns them with a pinned MAFFT version, unless a published alignment is used.
- It writes `web/public/library/<id>.fasta` and `<id>.json`. The JSON records the accessions, source database, retrieval date, license, citation, aligner and version (or the published alignment's citation), and the sha256 of the FASTA.
- Size caps: at most 30 taxa and 2,000 sites per dataset, so bootstrap stays responsive in the browser.
- The committed FASTA is the source of truth. CI never fetches. A CI test checks each FASTA against its sha256 and the caps, and that the engine parses it.
- Licenses are listed in `THIRD_PARTY_NOTICES.md` and on the Licenses page. A dataset whose license does not allow redistribution is not included.

### 5.3 Open dataset
- An "Open dataset" sheet in the sandbox lists each dataset: name, taxa × sites, DNA or protein, a one-line "good for", and the source and license, with a link to the provenance.
- Loading a dataset goes through the same path as opening a file.

## 6. Sandbox and UI

### 6.1 Model menu and gap treatment
- The sandbox correction menu adds `F84`, `K2P_PHYLIP` (with a κ input, default 2.0), `Poisson`, and `JTT_MEGA` if it exists, each offered only for its alphabet.
- A gap-treatment control: Pairwise (default), Complete, Partial with a cutoff field (default 95).
- Built-in lessons do not show the new options and keep their results.

### 6.2 Removed columns
- NeoPhylo has no whole-alignment view; sites are shown in the pair panel's site grid. Columns removed by the filter are marked there, distinct from the existing dimming of non-comparable sites, and a count appears next to the gap-treatment control ("312 of 1,480 sites removed by complete deletion").
- Keyboard and screen-reader users get the same count in a live region.

### 6.3 `.meg` import and export
- Open accepts `.meg` next to FASTA and PHYLIP. Parser notices (ignored commands) are shown.
- Export gains `.meg` for the current alignment.

### 6.4 Layout
- New sheets and controls follow the v1.3 tokens and breakpoints. Below 1,024 px the dataset sheet opens full-screen, as other sheets do. Touch targets are at least 40×40 px, including plain links.

## 7. MEGA companion content

### 7.1 Handouts
Four handouts, in the same format as the v1.4 PHYLIP lab packs:
1. JC69 vs K2P
2. NJ vs UPGMA
3. 100 bootstrap replicates
4. Interpreting support

Each has: objectives; handout text; a "load this lab" button that loads the dataset and sets the model, gap treatment and replicate settings; a table mapping each MEGA menu path and setting to the matching NeoPhylo setting; a "what MEGA shows you vs what NeoPhylo shows you" note; a print view; and a link to the matching exercise file. Expected numbers come from the committed MEGA fixtures, never from NeoPhylo's own output.

### 7.2 "Coming from MEGA?"
A guide next to "Coming from PHYLIP?", linked from the header. It covers MEGA terms and their NeoPhylo names, the three gap treatments, which numbers match MEGA, which are validated against PHYLIP instead (if `JTT_MEGA` exists), and why bootstrap values agree only within sampling noise.

### 7.3 Lab index
The lab index lists both families (PHYLIP and MEGA) with objectives, time estimates and settings.

### 7.4 Review
- Each handout and the guide are reviewed for accuracy by a phylogeneticist reviewer before release. This is an **owner gate** under the conductor rules, scheduled per handout.
- Lesson content checks apply: no spoilers before the student acts, no hard-coded numbers that can mismatch, no "probability" readings of support.

## 8. Testing

- **Engine:** MEGA parity (§3.5); property tests (§3.6); `NeoError` tests for invalid cutoffs, empty filters and malformed `.meg`; fuzzing of the `.meg` parser and the new exercise fields; all existing tests unmodified.
- **Library:** sha256, size caps and parse checks for every dataset; provenance JSON validated against a small schema.
- **Schema:** v4 examples validate; v1–v3 files migrate; broken files are refused with the right message.
- **Web:** Vitest for the new state and URL fields; Playwright for opening each dataset, `.meg` import and export round trip, switching gap treatments (with the removed-column count), the new sandbox models, and each handout's "load this lab" button.
- **Visual:** snapshots of the dataset sheet, removed columns in the pair panel, the gap-treatment control and each handout's print view, in both themes, at 768, 1,024 and 1,280 px. Baselines are owner-approved.
- **Old links:** the v1.1–v1.4 link corpora restore identically.
- **Accessibility:** axe checks on every new page and sheet.

## 9. Milestones inside v1.4b

The plan will order the work so each step is testable on its own. Proposed order:
1. MEGA-CC install, `.mao` files, generator, first fixtures (DNA and protein, all three gap treatments). This decides `JTT_MEGA` and the partial-cutoff boundary.
2. Engine: `SiteFilter` and bootstrap with a filter.
3. Engine: `Poisson`, and `JTT_MEGA` if needed.
4. Engine: `.meg` parser and writer.
5. Exercise format v4, state and URL fields.
6. Data library: build script, datasets, provenance, MEGA fixtures on the handout datasets.
7. UI: sandbox model menu, gap-treatment control, removed columns in the pair panel, `.meg` import and export, Open dataset sheet.
8. Handouts 1–4, each with its owner-gated review, then "Coming from MEGA?" and the lab index.
9. Release checkpoint.

## 10. Open items for the plan
These are not blockers for this spec. Each gets an answer in the plan:
- The MEGA-CC version, and MEGA's defaults for gap treatment and site coverage.
- MEGA's printed precision for each output.
- Whether MEGA's JTT matches `Jtt` (§3.3).
- Whether MEGA applies the site filter before or after bootstrap resampling, with a source (§3.2).
- The accessions for each dataset and the MAFFT version (§5).
- The exact JSON casing of the new model identifiers (§3.3).

## 11. Risks
- **MEGA-CC behaves differently from the GUI** in defaults or output precision. Mitigated by fixture-first work (milestone 1) and by handouts that list every setting rather than relying on defaults.
- **Frozen oracle.** CI cannot regenerate MEGA fixtures, so a broken fixture is caught only by review. Mitigated by recording the version and `.mao` hashes and by the fixture guard's owner approval.
- **`JTT_MEGA` adds naming confusion.** Mitigated as for `K2P_PHYLIP`: a distinct name, a visible note and a divergence test.
- **Dataset licensing.** Mitigated by recording a license per dataset and dropping any dataset that cannot be redistributed.
- **Review load** from four owner-gated handouts. Mitigated by scheduling reviews per handout.
