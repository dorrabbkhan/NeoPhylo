# NeoPhylo v1.3: Design system, bundled fonts and responsive layout, design spec

Status: Draft for review · Date: 2026-10-21 · Repo path: `docs/superpowers/specs/2026-10-21-neophylo-v1.3-design-system-design.md`
Builds on the v1, v1.1 and v1.2 specs. **No scientific behavior changes in this release.**

## 1. Purpose and decision record

v1.3 makes NeoPhylo credible at first glance, before spring-term outreach and pilots: a consistent
light-first look that works on projectors and in print, readable on half-width windows and tablets, and
figures that look identical in any program. It also pays down the structural debt that slowed v1.2.

**Decisions (owner, brainstorming 2026-10-21):**
- **Direction:** refine the current look into a consistent system, **light-first**, with a **minimal
  identity** (wordmark and icon). No full rebrand.
- **Fonts:** **Inter** (interface and tree text, tabular numbers) and **JetBrains Mono** (sequences, code),
  both SIL Open Font License, self-hosted and embedded in SVG exports.
- **Screen support:** fully usable down to **768 px** wide; phones work but aren't optimized.
- **Implementation:** plain CSS **design tokens** defined once in TypeScript, shared by the app and the
  export renderer. No Tailwind, no component library.

**Success criteria:**
1. Every screen uses tokens only (no hard-coded colors or font sizes); text contrast is WCAG AA in both
   themes.
2. At 768, 1,024, 1,280 and 1,920 px: no sideways page scrolling, every leaf of trees up to 40 leaves
   visible, the stepper always visible.
3. An exported SVG renders identically in a browser with system fonts blocked.
4. Visual regressions are caught automatically by snapshot tests against owner-approved baselines.
5. All existing engine, parity, lesson-premise and old-link tests pass unmodified.

## 2. Scope

### 2.1 In v1.3
Design tokens and both themes; theme toggle; bundled fonts (with font-aware layout and SVG embedding);
minimal identity (wordmark, icon, favicons, social image); responsive layout; full-screen sheets and a
"More" menu below 1,024 px; touch targets; presenter mode; first-visit tour; empty and loading states;
Sandbox sample datasets; saturation progress feedback; reduced-motion support; skip link; lazy-loaded
KaTeX; `session.ts` split; visual snapshot tests; light print-friendly exports with a "match screen theme"
option.

### 2.2 Non-goals
Phone-optimized layouts; a full brand redesign; Tailwind or component libraries; translations; new
analyses or lessons; any change to distances, trees, bootstrap, simulation or lesson results.

## 3. Design tokens

### 3.1 Single source
- `web/src/design/tokens.ts` exports typed tokens: `color` (per theme), `font`, `size` (type scale),
  `space`, `radius`, `shadow`, `semantic`.
- A Vite plugin generates `tokens.css` (custom properties under `:root[data-theme="light"]` and
  `:root[data-theme="dark"]`) at build time. It's generated, never committed or hand-edited.
- The tree renderer and SVG/PNG export import `tokens.ts` directly.

### 3.2 Token set
- **Colors** (per theme): `bg`, `surface`, `surface-2`, `border`, `text`, `text-muted`, `accent`,
  `accent-contrast`, `focus`.
- **Semantic colors:** `support-weak`, `wrong-clade`, `saturation-hatch`, `highlight`, `danger`,
  `success`.
- **The heatmap keeps viridis** (colorblind-safe) in both themes.
- **Type scale (px):** 12, 14, 16, 20, 24, 32. **12 px is the minimum for any text**, including tree
  labels and heatmap cells.
- **Spacing (px):** 4, 8, 12, 16, 24, 32, 48. **Radii:** 4, 8, 12. **Shadows:** `sm`, `md`.

### 3.3 Themes
- `data-theme` on `<html>`. **Default: light**, regardless of the operating-system setting.
- A header toggle (`aria-pressed`) switches themes. The choice is stored per device under
  `neophylo.theme` (with try/catch around storage) and is **not** part of shared links.
- **Contrast:** text pairs ≥ 4.5:1; large text, interface components and graphics ≥ 3:1 (WCAG 2.2 AA),
  in both themes.

### 3.4 Discipline
A test scans `web/src/**/*.css` and inline styles for literal colors and font sizes. Any found outside
`tokens.ts` fails the build.

## 4. Fonts

### 4.1 Files
- **Inter**, weights 400/500/600; **JetBrains Mono**, weight 400.
- Exact upstream versions are recorded in `web/public/fonts/README.md`.
- Subsets: `latin`, `latin-ext`, `greek`, `cyrillic` (standard Unicode ranges), as `woff2`, keeping the
  OpenType features `kern` and `tnum`.
- Produced by `scripts/fonts/subset.sh` (fonttools `pyftsubset`, pinned version) and committed under
  `web/public/fonts/` together with the script.
- **Budget:** all subsets of all weights ≤ 200 KB total.

### 4.2 Loading and measuring
- `@font-face` with `font-display: block`.
- Layout and text measurement wait for `document.fonts.load()` of the faces in use, up to 3 s. On timeout,
  layout proceeds with fallback metrics and **re-lays out once** when the fonts arrive.
- The v1.2 measured-text-width code is kept; it now measures the same font on every machine.
- The service worker precaches all font files.

### 4.3 SVG export embedding
- Exported SVGs include `@font-face` rules with the needed subsets as base64 data URIs.
- Subsets are selected by the Unicode ranges present in the figure's text; weights only as used.
- PNG export is rendered in-browser and needs no embedding.

### 4.4 Licensing
Both fonts are OFL-1.1. Add notices to `THIRD_PARTY_NOTICES.md` and the Licenses page (the v1.2 license
aggregation includes `web/public/fonts/`).

## 5. Minimal identity

- **Wordmark:** "NeoPhylo" in Inter 600, single color (`text`), with the icon at its left.
- **Icon:** a simple branching mark (SVG), drawn with the `accent` color.
  - **Owner gate:** three options are produced; the owner picks one before any asset is generated.
- **Assets generated by `scripts/brand/generate.ts`** (rendered via Playwright, already a dependency):
  - `favicon.ico` (16/32/48 px)
  - `apple-touch-icon.png` (180 px)
  - PWA icons 192/512 px (including maskable versions)
  - an `og-image.png` (1200×630: wordmark, icon and the tagline "Learn how phylogenetic trees are built,
    step by step")
- Used in the header, manifest, `<meta property="og:image">` and the README.

## 6. Layout and interaction

### 6.1 Breakpoints
| Name | Width | Arrangement |
|---|---|---|
| wide | ≥ 1,280 px | Controls · center (trees, matrix, prompts) · explanation, as today |
| medium | 1,024–1,279 px | Controls in a **Settings drawer** (header button); explanation below the center |
| narrow | 768–1,023 px | **Single column:** true tree, inferred tree (full width each), matrix, prompts, explanation (collapsible); controls in the drawer |
| compact | < 768 px | Same as narrow, scrollable; not specially optimized |

### 6.2 Invariants at every width
- Tree panels keep their **natural height** (28 px per leaf + padding, from v1.2). Long names cause
  **horizontal** scrolling inside the tree panel; text never shrinks. Inner vertical scrolling only above
  40 leaves.
- The **stepper bar is pinned** to the bottom, respecting safe-area insets.
- **No sideways scrolling of the page.**
- Below 1,024 px, dialogs (pair panel, replicate panel, PHYLIP help) become **full-screen sheets**, with
  focus trapping and Esc to close.

### 6.3 Header
- Wordmark, Lesson/Sandbox, Lessons, **theme toggle**, **presenter toggle**.
- Below 1,024 px, "Coming from PHYLIP?", Licenses, Source code and Help move into a **"More"** menu (the
  menu-button pattern, keyboard operable).

### 6.4 Settings drawer
Left-side overlay with the Simulation, Analysis, How-sure, Import and Export sections; focus trap; Esc and
backdrop click close it; it restores focus to its button.

### 6.5 Touch
Under `@media (pointer: coarse)`: interactive targets (buttons, matrix cells, tree branches in
`predict_branch`) are ≥ 40×40 px.

### 6.6 Presenter mode
- `data-presenter` on `<html>` scales the type and spacing tokens by 1.5, hides the controls column and the
  drawer button, and enlarges the step buttons.
- Toggled from the header (`aria-pressed`) and stored per device under `neophylo.presenter`; not in links.

### 6.7 First-visit tour
- Four steps: the stepper, the two trees, the matrix, the Concept/Math toggle. Next/Back/Skip; keyboard
  operable; an `aria-live` description.
- Shown once per device (`neophylo.tourSeen`), and **not shown** when the page opens with `lesson=` at a
  step > 0, or with `#x=` state. Reopened from More/Help → "Take the tour".

### 6.8 Empty and loading states (exact texts)
- **Engine loading:** "Loading the NeoPhylo engine…" (skeleton panels, no blank screen).
- **Sandbox without data:** "Paste or upload sequences, or try a sample:" with buttons **"Cytochrome c
  (protein)"** and **"Weak-support example (DNA)"**.
  - The weak-support sample is `web/public/samples/weak-support.fasta`, generated deterministically by
    `scripts/samples/weak_support.py` (the checkpoint-11 recipe, seed recorded).
- **Bootstrap idle:** "Run the bootstrap to see how strongly the data supports each grouping."
- **Consensus tabs before a run:** "Available after a bootstrap run."

### 6.9 Saturation progress feedback
After a fix that doesn't fully resolve saturation: "Still saturated at length {n}: {k} pair(s) remain.
Try again, or choose another fix."

### 6.10 Accessibility
- Focus outlines use the `focus` token (≥ 3:1 against neighbors).
- A **"Skip to content"** link.
- Under `prefers-reduced-motion`, transitions are disabled; play mode still steps, without animation.
- axe checks clean in both themes and at all four widths.

## 7. Architecture changes

### 7.1 Splitting `web/src/state/session.ts`
- Into `state/lesson.ts` (exercise, prompts, sequencing gates), `state/analysis.ts` (alignment, model,
  method, steps, reroot display), `state/bootstrap.ts` (run state, settings, results), `state/ui.ts`
  (mode, theme, presenter, drawers, tour) and the existing `state/url.ts`.
- `state/session.ts` composes them and **keeps its public API identical** (`Session`, `Action`, `reducer`,
  `initialSession`), so callers are untouched.
- Each module ≤ 400 lines.
- **Pure move:** no behavior change; every existing unit, e2e and old-link test passes unmodified.

### 7.2 Lazy KaTeX
- KaTeX is loaded by dynamic import the first time Math content renders, with a "Loading formulas…"
  placeholder.
- Precached by the service worker.
- Main bundle: KaTeX excluded from the initial chunk.

### 7.3 Exports
- Default **print palette** = light-theme tokens, whatever theme is on screen.
- Export menu option **"Match screen theme"** (off by default).
- Same layout code as the screen (v1.2 rule); fonts embedded per §4.3.

### 7.4 Viewer preferences
`neophylo.theme`, `neophylo.presenter`, `neophylo.tourSeen`: device-local, read with try/catch, never
encoded in URLs.

## 8. Validation

### 8.1 Unchanged behavior
- The engine, PHYLIP/R/`consense` parity, golden hashes and lesson premises pass unmodified.
- The v1.1 (`v1-urls.json`) and v1.2 (`v2-urls.json`) link corpora open identically (same step-0 matrix
  and step).

### 8.2 New tests
- **Token discipline** (§3.4).
- **Contrast:** a unit test computes WCAG contrast for every token pair used for text, focus and graphics,
  in both themes.
- **Fonts:**
  - `document.fonts.check()` for the bundled faces after load
  - measured label width vs `getComputedTextLength()` within 0.5 px
  - an exported SVG contains `@font-face` data for exactly the needed subsets
  - an exported SVG rendered in a browser page with system fonts blocked (only the embedded faces
    available) matches the in-app figure screenshot within the snapshot tolerance
- **Layout** (e2e at 768×1024, 1024×768, 1280×800, 1920×1080):
  - no horizontal page scroll
  - all leaves of cytochrome c (8) and bootstrap-basics (8) visible without scrolling the tree panels
  - stepper visible
  - dialogs are full-screen sheets below 1,024 px
  - the drawer and More menu work by keyboard
- **Accessibility:** axe in both themes at all four widths; reduced motion disables transitions; the skip
  link works.
- **Performance:**
  - fonts ≤ 200 KB in total
  - initial JS (gzip) ≤ the v1.2 initial bundle minus KaTeX plus 5 KB
  - time to first rendered tree on throttled "Fast 3G" in Chromium no worse than v1.2 by more than 10%

### 8.3 Visual snapshots
- Playwright `toHaveScreenshot`, **Chromium only**, animations disabled, bundled fonts,
  `maxDiffPixelRatio` 0.001.
- **Scenes:** cytochrome c rooted and computed after a seeded bootstrap run; the weak-support sample after
  a run; a 4-taxon tree; the replicate panel; bootstrap-basics' final step after the full note sequence;
  an exported SVG rendered back.
- Each scene at **1920×1080, 1024×768 and 768×1024**, in **both themes**.
- Baselines live in `web/e2e/__screenshots__/` (test files, an exception to the "no committed review
  screenshots" rule), owned by the owner in `CODEOWNERS`.
- The CI job `visual` runs on PRs touching `web/**`; on failure it uploads diff images and links them in a
  PR comment.

### 8.4 Owner gates
1. The icon choice (§5).
2. The baseline approvals: after the snapshot setup (current look) and after the themes.
3. The final hands-on check: a real tablet or half-width window, presenter mode on a large screen, and a
   printed exported figure.

## 9. Risks
| Risk | Mitigation |
|---|---|
| Restyling subtly breaks things | Tokens first with the current colors (no visual change), themes in a separate task, snapshot diffs at each step |
| Session split changes behavior | Done first as a pure move; all tests and link corpora must pass unmodified |
| Snapshot flakiness | Bundled fonts, fixed viewports, animations off, Chromium only, a tiny tolerance |
| Font size or first-load regression | Subsets only; budgets in §8.2; precaching |
| Licensing | OFL notices in THIRD_PARTY_NOTICES and the Licenses page |
| Exports differ from the screen | Shared tokens and layout code; the blocked-fonts render test |
