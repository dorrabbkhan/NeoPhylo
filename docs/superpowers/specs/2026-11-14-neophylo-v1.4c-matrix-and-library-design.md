# NeoPhylo v1.4c: matrix input, lesson library and worksheets, design spec

Status: Draft for owner review · Date: 2026-11-14 · Repo path: `docs/superpowers/specs/2026-11-14-neophylo-v1.4c-matrix-and-library-design.md`
Builds on the v1, v1.1, v1.2, v1.3, v1.4 and v1.4b specs. Roadmap entry: `docs/roadmap.md` § v1.4c (narrowed by this spec: accession fetch moves to v1.9). Market check behind it: `docs/market/2026-11-14-market-check.md`.

## 1. Purpose and decision record

v1.4c lets a student or instructor start from a **distance matrix** instead of an alignment, the classic textbook "build the tree from this matrix" exercise, and turns NeoPhylo's lessons and labs into a **library** with learning objectives, **printable worksheets with engine-computed answer keys**, and an **instructor guide**.

**Context (owner, 2026-11-14):** there is no pilot and no outreach yet; the owner is building until the product is solid and very impressive before showing anyone. "Impressive" is meant for every audience at once: instructors (ready-made worksheets and keys), textbook-style courses (matrix exercises) and phylogeneticists (validated numbers).

**Decisions (owner, brainstorming 2026-11-14):**
- **Matrix input, full scope (option C):** open `.meg` and PHYLIP matrix files, paste a matrix, or type one into a grid; matrix exercises in exercise files, the editor and lessons.
- **Worksheets, both kinds (option C):** an in-app companion sheet filled in while using a lesson, and a pencil-and-paper sheet done without the app and checked in it afterwards. The paper sheet is the v1.4c emphasis.
- **Answer keys sit behind an "I'm an instructor" step** with a warning (option B). This is a signal, not security: there are no accounts.
- **Accession fetch moves to v1.9** (option A): fetched sequences are unaligned and NeoPhylo cannot align until v1.9, so fetch would lead to a dead end. The privacy question (first outside request) moves with it. The browser still never makes an outside request in v1.4c.
- **Architecture (approach A, §3):** the matrix is a third kind of exercise data; existing lesson, sandbox, URL, export and editor paths handle it, and alignment-only features switch off.

**Calls made by the conductor (owner may overrule while reviewing):** marked *(conductor's call)* where they appear.

**Success criteria:**
1. NJ and UPGMA on a supplied matrix match PHYLIP `neighbor` (matrix input), `ape::nj` / `phangorn::upgma`, and MEGA-CC (matrix `.meg` input) on committed fixtures, to each oracle's printed precision.
2. Every `.meg` and PHYLIP matrix fixture round-trips through NeoPhylo's parser and writer unchanged in value.
3. A matrix typed or pasted into the grid gives the same tree as the same matrix opened from a file.
4. NJ on an additive matrix derived from any tree recovers that tree (topology and branch lengths within floating-point tolerance); UPGMA does the same on ultrametric trees (property tests).
5. Every built-in lesson, every lab and every matrix exercise has an in-app worksheet; every exercise small enough to work by hand (§7.2) also has a paper worksheet. Every number in every answer key comes from the engine at render time. No answer-key number is typed into a content file.
6. The library page lists every lesson and lab with objectives, minutes and level; the instructor guide's 50-minute and 3-hour plans link only to things that exist.
7. All existing engine, parity, lesson-premise and old-link tests pass unmodified. No existing number changes.

## 2. Scope

### 2.1 In v1.4c
- Engine: a `DistanceInput` type, PHYLIP (square and lower-triangular) and `.meg` matrix parsers, a `.meg` matrix writer, NJ/UPGMA trace entry points that take a matrix, and "matrix from tree" (additive path lengths).
- Oracles: new PHYLIP `neighbor`, ape/phangorn and MEGA-CC fixtures on matrix input.
- Exercise format `schema_version` 5: `data.kind = "matrix"` and optional lesson metadata (§4).
- UI: matrix workspace in the sandbox (open, paste, grid), alignment-only panels switched off, matrix exports; editor support; negative-branch notice.
- Two new built-in matrix lessons (§7.4).
- Library page, worksheets (in-app and paper) with gated answer keys, instructor guide.
- MEGA bootstrap handout: a note on MEGA 12's Adaptive replicate option if the GUI offers it (§8.4).

### 2.2 Non-goals
- Accession fetch and any outside network request (v1.9).
- Alignment of any kind (v1.9).
- Bootstrap, pair panel, saturation chart, gap treatment or models on matrix input. There is no alignment to resample or correct.
- Per-student variants, auto-checked tasks or completion codes (v1.5). Worksheets are static for a given exercise.
- Fitch-Margoliash, BIONJ, minimum evolution (v1.8). Matrix input feeds only NJ and UPGMA.
- Hiding answer keys for real (needs accounts; v3.0).
- Changes to existing lessons' content or results. They only gain metadata (§4.2).

## 3. Approaches considered

- **A. Matrix as a third kind of exercise data** *(chosen)*. Lesson, sandbox, URL, export and editor code handle it; alignment-only panels are switched off by one capability check. Worksheets are generated from any exercise. Everything that exists today works on matrices without being rebuilt. Cost: a careful pass over every place that assumes an alignment exists.
- **B. A separate matrix workspace** with its own view and state. Lower risk to existing sessions, but duplicates the stepper, links and exports, and matrix exercises would not fit the editor or lessons. Rejected because it works against the full scope (option C).
- **C. Convert a matrix into a fake alignment.** Rejected: numbers would come from invented data, breaking the rule that the reviewer compares the computed thing.

## 4. Exercise format v5 and state

### 4.1 Matrix data
`ExerciseData` gains `Matrix { names: Vec<String>, lower: Vec<f64>, source: Source }`:
- `names` length `n`, 3 ≤ `n` ≤ `MAX_TAXA` (200); names unique, same rules as alignment labels.
- `lower` is the strict lower triangle in row order (`n·(n−1)/2` values: row B has d(B,A); row C has d(C,A), d(C,B); …). The diagonal is implicitly zero. *(conductor's call: lower triangle only, so a stored matrix can never be asymmetric.)*
- Every value finite and ≥ 0. Zero off-diagonal values are allowed (identical taxa).
- `source` as for embedded alignments (citation, license; `accessions` may be empty).
- `alphabet` is not meaningful for a matrix. The plan decides whether the field becomes optional for `kind: "matrix"` or takes a fixed value; either way v1–v4 files are unaffected.
- `analysis.correction`, `kappa`, `site_filter` and `bootstrap` are refused on matrix exercises with a `NeoError` naming the field. `analysis.method` (NJ or UPGMA) applies.
- Prompts: `predict_pair` and `note` work unchanged; `predict_branch` (bootstrap) is refused.

### 4.2 Lesson metadata
Optional `meta` on every exercise: `objectives: [string]`, `minutes: u32`, `level: "intro" | "intermediate" | "advanced"`, `prepares_for: [id]` (lesson or lab ids, validated to exist by a repo test). All six built-in lessons gain `meta`. Adding `meta` changes no step, prompt or number; the lesson-premise tests prove it. Lab files keep their existing `lab.objectives` and `lab.minutes`; the library reads either.

### 4.3 Migration and URL
- v1–v4 files load as today. v5 adds only the two optional things above.
- Matrix sandbox data and matrix exercises travel in the `#x=` fragment (lz-compressed, never sent to a server), like imported alignments. A 200-taxon matrix may make a long link. There is no link-length warning today; the plan measures realistic sizes and, if links get impractically long, adds a warning that suggests exporting the matrix file instead, never a failure.
- The v1.1–v1.4b old-link corpora restore identically; a new v1.4c corpus is added.

## 5. Engine

All new code is in `crates/neophylo-core`, pure Rust, uses `libm`, follows the determinism rules in `docs/architecture.md`, and never panics on any input.

### 5.1 Parsing
- **PHYLIP:** `n` on the first line, then rows of name + values, as `neighbor` reads them. Square and lower-triangular forms (`neighbor`'s `L` option); strict 10-character and relaxed names via the existing `NameMode`; values may wrap across lines. A square matrix whose upper and lower triangles differ is refused with the first differing cell named, and the UI offers "use the lower triangle" *(conductor's call)*. `dnadist`/`protdist` saturation markers (`-1`) and any negative or non-numeric value are refused with the cell named.
- **`.meg`:** the distance-matrix form MEGA writes (`!Format DataType=Distance`, lower-left or upper-right layout, `#name` lines, `?` or `n/c` for missing). Missing cells are refused with the cell named; NJ needs a complete matrix. The current refusal ("planned for v1.4c") is replaced by real parsing.
- **Paste:** the same two parsers, plus a tolerant tabular form (whitespace- or comma-separated, optional header row of names, square or lower triangle) for matrices copied from PDFs or spreadsheets. If the parse is ambiguous (for example, no names), the UI asks rather than guessing.
- Diagonal cells, when present, must be zero (refused otherwise, cell named).

### 5.2 Trees from a matrix
NJ and UPGMA already run on a `DistanceMatrix`; new entry points take the parsed matrix directly and produce the same step traces (Q matrices, joins, branch lengths) the stepper uses today. Negative NJ branch lengths are kept as computed (current behavior) and reported in the trace so the UI can flag them.

### 5.3 Matrix from a tree
`additive_matrix(tree) -> DistanceInput`: patristic (path-length) distances between leaves, for the editor's "derive from tree" route. An optional rounding to `k` decimals (default none) helps textbook-friendly integers; when rounding is on, the editor says the matrix may no longer be exactly additive.

### 5.4 Writing
`.meg` distance-matrix writer (lower-left) next to the existing PHYLIP matrix writer, so a matrix round-trips through both formats.

### 5.5 Validation
- **PHYLIP `neighbor`** reading matrix files (NJ and UPGMA): new fixtures from `fixtures/generate_phylip.sh`, including a square and a lower-triangular input and one non-additive matrix that yields a negative branch.
- **ape/phangorn:** `ape::nj(as.dist(m))`, `phangorn::upgma`, full precision.
- **MEGA-CC:** matrix `.meg` inputs with committed `.mao` files, run locally and frozen like the v1.4b fixtures.
- **Worked examples:** the existing `fixtures/worked/nj_wikipedia5.json` and `upgma_wikipedia5.json` now also run through the matrix parser path.
- New fixtures are added in their own PR (the fixture guard is whole-PR) and are an owner gate.

### 5.6 Property tests and fuzzing
New proptest functions (existing strategies are not edited, to keep saved seeds valid):
- parse ∘ write ∘ parse is the identity on values for both formats;
- NJ on `additive_matrix(t)` recovers `t`'s unrooted topology and branch lengths within tolerance;
- UPGMA on an ultrametric tree's additive matrix recovers it;
- grid entry and file entry of the same matrix give identical traces.
Fuzz targets for both matrix parsers and the tolerant paste parser; every input yields `Ok` or `NeoError`, never a panic.

## 6. Sandbox and editor UI

### 6.1 Getting a matrix in
The import panel gains a "Distance matrix" path with three routes into the same matrix workspace: open file (`.meg`, PHYLIP), paste, or **type into a grid**. The grid is lower-triangle only, starts at 5 taxa, adds or removes taxa, edits names inline, and validates each cell as typed (number, ≥ 0). "Build tree" stays disabled until the matrix is complete and valid, and the reason is shown next to it.

### 6.2 What changes in a matrix session
- The stepper, Q matrix, matrix heatmap, explanation panel and tree work as today on the supplied matrix; the method toggle switches between NJ and UPGMA.
- Alignment-only panels (pair panel, saturation chart, model menu, gap control, bootstrap) are **hidden**, with one line saying why ("This tree was built from a distance matrix, so there are no sequences to compare or resample") *(conductor's call: hidden with one line, not shown greyed out)*.
- **Negative branches:** the existing negative-branch notice and its "Set negative branches to zero" toggle (`TeachingNotices.tsx`, `clampNegative`, off by default) apply unchanged. No new default and no change to existing visuals. Exports keep carrying the computed values as today. The notice text may gain one matrix-specific sentence ("this matrix is not perfectly tree-like"), shown only in matrix sessions.

### 6.3 Exports
Newick, SVG/PNG (screen layout), the matrix as PHYLIP or `.meg`, and an R script that rebuilds the tree with `ape::nj(as.dist(m))` or `phangorn::upgma`.

### 6.4 Editor
The editor's data step offers "Start from a matrix": type or paste one, or **derive it from the drawn tree** (§5.3). Prompts can be added at join steps as today. The preview and share link work as for other exercises. Choosing the matrix route hides the simulation settings.

### 6.5 Layout and performance
Matrix workspace, grid and notices meet the v1.3 design-system rules (both themes, ≥ 12 px text, 768/1,024/1,280 px and narrow layouts, ≥ 40×40 touch targets). The library, worksheet and guide pages are lazy-loaded so the initial-JS budget does not grow *(conductor's call, following the owner's earlier lazy-loading preference)*.

## 7. Library, worksheets and instructor guide

### 7.1 Library page
`?library`: one page listing every built-in lesson, lab and bundled dataset (the v1.4b data library in `web/src/library/`, opened today through "Open dataset" and the `ds=` key) as a card with type, level, minutes, objectives, "prepares for / follows", and actions (open, in-app worksheet, paper worksheet, answer key). Filters: type (lesson, PHYLIP lab, MEGA lab, dataset), level, ≤ 30 minutes. Dataset cards show source and license and open the dataset; they have no worksheet *(conductor's call: one library, not two features with the same name)*. The header links to the instructor guide. `?labs` keeps working and opens the library filtered to labs, so existing links and the lab index's print view still work *(conductor's call)*.

### 7.2 Worksheets
Generated, never written separately:
- **Paper worksheet** (exercises with at most 8 taxa; larger ones get only the in-app worksheet, because a printed matrix stops being workable by hand) *(conductor's call)*: the matrix, then one block per hand-worked join (row sums, Q values, chosen pair and whether it is the closest pair, branch lengths, new distances), then "finish the tree and sketch it". For `n` ≤ 6 every join is hand-worked; for 7–8 the first two, the rest computed in the app *(conductor's call; the editor lets the author change the count)*. A link and QR code open the exact exercise (`#x=`), so it works offline. UPGMA worksheets use cluster averages instead of Q.
- **In-app worksheet** (every lesson and lab): one item per prompt ("At step 3, which pair did you predict, and why?") plus space for a sentence after each note. It is filled in on paper while using the app.
- **Answer key:** the same layout with every value filled in, computed by the engine at render time from the exercise. Displayed to the precision the app shows. Each key lists one common mistake per join where the closest pair is not the joined pair (detected by the engine, not written by hand).
- **Ties in keys:** when the engine reports a tie at a join, the key marks every tied pair as a correct answer and says which one NeoPhylo (and PHYLIP, by input order) picks; later steps follow the app's choice *(conductor's call)*.
- **Lab keys and resampling:** values that come from random resampling (bootstrap labs) are shown as the seeded NeoPhylo run's values with a fixed caption: students' numbers from MEGA or PHYLIP will differ by sampling noise. Any tolerance or range wording waits for the owner's ruling on #126 *(conductor's call)*. Deterministic values (distances, trees) are shown as computed.
- **Existing lessons:** their in-app worksheets reprint each prompt's text as it is; lesson content is not edited in v1.4c.
- Printing uses the light-paper print styles from the lab handouts (`LabPrintStyles`), checked by the same print-colour tests.

### 7.3 Answer-key gate
Opening an answer key shows a confirmation ("Answer keys are for instructors. Students: work the sheet first.") with "I'm an instructor". The choice lasts for the browser session. The student worksheet never includes answers. The guide states plainly that this is not access control.

### 7.4 New lessons
- **`nj-by-hand`**: a five- or six-taxon textbook-style integer matrix with **no tie at any join**, where the closest pair is not joined first; the student predicts each join before it is revealed. The well-known `nj_wikipedia5` matrix is not used as-is: it has a tie at step 2 (Q = −28 for two pairs, `fixtures/worked/nj_wikipedia5.json`). The plan picks the matrix (for example a one-cell change to it) and adds a worked fixture for it *(conductor's call)*.
- **`upgma-vs-nj-matrix`**: an additive matrix derived from a non-ultrametric tree, where NJ recovers the tree and UPGMA does not.
Both follow the lesson-content rules (no spoilers before the student acts, no hard-coded numbers in text, numbers in notes come from the engine) and are owner-gated reviews.

### 7.5 Instructor guide
`?guide`, printable: how NeoPhylo is organised; a **50-minute class plan** and a **3-hour lab plan**, each built from library items with timings; what each answer key contains; the answer-key caveat; how to make a matrix exercise in the editor and share it. Content lives as markdown in the repo, rendered like handouts (never raw HTML). A repo test checks every library link in the guide exists. Reviewed by the phylogeneticist reviewer (owner gate).

## 8. Content checks and other items

### 8.1 Review
Each new lesson and the guide are owner-gated reviews. Worksheets are generated, so the reviewer checks the generator once on a sample of each kind, plus every built-in worksheet's rendered PDF.

### 8.2 Numbers in text
No number derived from data appears in new lesson, guide or worksheet text unless it is computed. A test greps the new content files for digits in prompt and note text that are not step numbers or allowed constants. Existing lessons and labs (which do quote numbers, for example `cytochrome-c` and `bootstrap-basics`) are on an allowlist and unchanged *(conductor's call)*.

### 8.3 Accessibility
The grid is a real table with labelled inputs, arrow-key navigation and screen-reader announcements for validation errors. axe checks on every new page and sheet.

### 8.4 MEGA Adaptive bootstrap
The plan checks MEGA 12's GUI for an "Adaptive" bootstrap replicate option and its default. If the GUI offers it, the `mega-bootstrap-100` handout tells students to choose a fixed 100 replicates. Handout edits are an owner-gated review.

## 9. Testing

- **Engine:** oracle parity (§5.5); property tests and fuzzing (§5.6); `NeoError` tests for every refusal (asymmetric, negative, missing, non-zero diagonal, too few or too many taxa, duplicate names, bootstrap or model fields on matrix exercises). All existing tests unmodified.
- **Schema:** v5 examples validate; v1–v4 files load unchanged; broken matrix exercises are refused with the right message.
- **Web:** Vitest for matrix state, URL and grid validation; Playwright for opening each format, pasting each form, typing a matrix, building NJ and UPGMA, the negative-branch notice in a matrix session, exports round trip, editor matrix route (both paths), library filters, each worksheet kind, the answer-key gate, and `?labs` still working.
- **Answer keys:** a test renders every built-in answer key and compares each number with the engine trace for that exercise.
- **Visual:** snapshots of the matrix grid, a matrix session, the library page, one paper worksheet, one answer key and the guide, in both themes and the standard widths; print views in light paper. Baselines are owner-approved.
- **Old links:** v1.1–v1.4b corpora restore identically; new v1.4c corpus.

## 10. Milestones inside v1.4c

1. Oracle fixtures for matrix input (PHYLIP, ape/phangorn, MEGA-CC), in their own owner-gated PR.
2. Engine: `DistanceInput`, parsers, writer, matrix entry points, `additive_matrix`, property tests, fuzzing.
3. Exercise format v5, state and URL.
4. UI: matrix import routes, grid, matrix session, notices, exports.
5. Editor: matrix route and derive-from-tree.
6. Lessons `nj-by-hand` and `upgma-vs-nj-matrix` (owner-gated), `meta` on all lessons.

8. Library page and instructor guide (owner-gated), MEGA Adaptive note.
9. Release checkpoint.

If v1.4c grows past its estimate, milestones 7–8 split off as v1.4d.

## 11. Left to the builder (plan)
- `alphabet` handling for matrix exercises (§4.1). Matrix exercises may carry a `reference` tree (needed by `upgma-vs-nj-matrix`).
- The exact `.meg` matrix variants MEGA-CC 12.1.4 writes and reads (layouts, missing markers, precision).
- `neighbor`'s printed precision for matrix-input runs and how it handles ties on integer matrices (fixtures must avoid ties, as today).
- The tolerant paste parser's exact grammar and its ambiguity prompts.
- Link length for large matrices (§4.3).
- Grid component details within the design system.
- QR code generation without a new heavy dependency (or a vetted small one, recorded in THIRD_PARTY_NOTICES).

## 12. Risks
- **Assumptions that an alignment exists** are spread through the app. Mitigated by one capability check, Playwright coverage of every hidden panel, and the old-link corpora.
- **Integer textbook matrices produce ties** (equal Q values), where tools may break ties differently (the famous Wikipedia example has one). Mitigated by tie-free fixtures and lesson matrices, the existing tie notice ("Tie: chosen by input order.") in the UI, and tie-aware answer keys (§7.2).
- **Generated worksheets read awkwardly** for some exercises. Mitigated by reviewing rendered PDFs of every built-in worksheet before release.
- **The answer-key gate is mistaken for security.** Mitigated by plain wording in the dialog and the guide.
- **Review load** from two lessons, the guide and a handout edit. Mitigated by scheduling reviews per item.
