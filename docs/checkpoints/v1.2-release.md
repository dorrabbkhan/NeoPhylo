# v1.2 release checkpoint — bootstrap, consensus, reference rooting

Owner-run manual checklist before tagging `v1.2.0`, modeled on the v1.1
release checkpoint (v1.1 plan Task 14 step 5). Everything automated is
already green — `E2E=1 RPARITY=1 FUZZ=1 ./scripts/check.sh` — so this is
the pass a machine can't do: play it like a student, look at it, and
take the analysis out of the app and back in.

Use the deploy preview of the release-candidate commit, not a dev
server. Record findings inline under each item; anything blocking goes
back as a `fix/` branch before the tag.

## 1. Every lesson, played as a student

Play each lesson start to finish with no devtools open:

- [ ] `nj-basics` — prompts gate, joins reveal, RF shown at the end.
- [ ] `upgma-fails` — the clock-breaks-UPGMA point lands.
- [ ] `saturation` — the fix buttons make progress; the model lever works.
- [ ] `protein-models` — the pair panel and the JTT likelihood curve.
- [ ] `cytochrome-c` — real data, reference comparison.
- [ ] `bootstrap-basics` — the `predict_branch` prompt gates Run; the
      verdict names the weakest group; the length change to 3,000 lifts
      its support; the closing note reads correctly.

Expected: no console errors, no stuck controls, spoiler rules hold
(support labels hidden until the run).

## 2. The bootstrap panel

- [ ] On a lesson (`nj-basics` or `cytochrome-c`), final step: run 100
      replicates. Progress text counts up ("Replicate k of N"), support
      labels appear live and settle at "Run complete".
- [ ] On Sandbox with a protein FASTA (`fixtures/inputs/protein/p6_150.fasta`,
      JTT): same run works; confirm the estimate/confirm path shows if a
      large run is requested (replicates at 1,000 on 200-taxon data).
- [ ] Change replicates or seed after a run: the stale-results line
      appears ("Results for 100 replicates, seed 1; settings changed…").
- [ ] Cancel mid-run on a slow case: it settles within ~1 s.
- [ ] Tiny trees (3–4 taxa imported in Sandbox): the panel explains how
      many groupings there are to test instead of erroring.

## 3. Consensus tabs

- [ ] After a run, tabs "Your tree with support" | "Majority-rule" |
      "Extended majority" | "Strict" switch the drawing; each draws a
      cladogram with support labels.
- [ ] The "Dropped from this consensus" line lists groupings with their
      support, or "None".
- [ ] Arrow keys move between tabs; the tabs are disabled before a run.

## 4. The replicate view

- [ ] Open "watch one replicate" from the panel; Previous/Next walk the
      replicates, ←/→ and Esc work.
- [ ] The column strip shows draw counts with zeros dimmed; the "U of L
      columns not drawn" count matches the strip.
- [ ] The replicate tree sits beside yours with differing groupings
      outlined.

## 5. Reroot toggle on cytochrome-c

- [ ] At the final step the inferred NJ tree is drawn rooted like the
      reference, wheat on its own branch, with the "same outgroup as the
      reference" caption.
- [ ] "Show as computed (unrooted)" restores the v1.1 unrooted drawing
      and caption; toggling back never moves or duplicates a support
      label.
- [ ] UPGMA analyses are not rerooted.

## 6. Offline

- [ ] Load the site once online, then go offline: reload works, a lesson
      loads, and a bootstrap run completes (the worker chunk is
      precached).

## 7. Exports round trip in R

- [ ] After a cytochrome-c bootstrap run, export "Consensus (Newick)"
      and the support-bearing Newick; read both with
      `ape::read.tree` — `node.label` equals the shown integer supports.
- [ ] Export the R script and run it: it reproduces the analysis and
      prints the bootstrap comparison (values within a few percent — the
      comment about differing random draws is in the script).
- [ ] Export SVG and PNG: support pills appear in both.

## 8. Tag the release

- [ ] All of the above signed off; CI green on `main`.
- [ ] `git tag v1.2.0` on the release commit; push the tag (production
      deploys on tags).
- [ ] Fill `date-released` in `CITATION.cff` (left for the owner in the
      Task 16 PR).
