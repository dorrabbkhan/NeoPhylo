# v1.4 release checkpoint — exercise editor, PHYLIP parity models, lab packs

Owner-run manual checklist before tagging `v1.4.0`, modeled on the v1.3
release checkpoint (v1.3 plan Task 16 step 5). Everything automated is
already green — `E2E=1 RPARITY=1 FUZZ=1 ./scripts/check.sh` — so this is
the pass a machine can't do: every lab at every width in both themes, a
keyboard-only run through the editor, a file carried to another
machine, a shared link that is too long, a printed lab page, and links
and exercise files that predate this release.

Use the deploy preview of the release-candidate commit, not a dev
server. Record findings inline under each item; anything blocking goes
back as a `fix/` branch before the tag. Spec references are to
`docs/superpowers/specs/2026-10-26-neophylo-v1.4-instructor-kit-design.md`.

## 1. Every lab and the lab index, both themes, all four widths

Open each lab page and the lab index in **light and dark** at **768,
1,024, 1,280 and 1,920 px** wide (§6.1, §6.2, §6.5):

- [ ] `dnadist-neighbor` — objectives, handout, settings table and the
      "what PHYLIP's outfile showed you vs what NeoPhylo shows you"
      note all render; "Load this lab" loads F84 + NJ with the pack's
      dataset.
- [ ] `protdist-neighbor` — same; "Load this lab" loads JTT + NJ.
- [ ] `seqboot-consense` — same; "Load this lab" loads F84 + NJ with
      replicates 100 and the chain fixture's seed, both locked.
- [ ] The lab index lists all three packs with their objectives, time
      estimates and settings; the header link and the "Coming from
      PHYLIP?" link both reach it.

At each width and in each theme:

- [ ] No sideways page scrolling; no clipped or overlapping labels;
      every leaf visible; all text ≥ 12 px.
- [ ] Below 1,024 px the table and Newick views open as full-screen
      sheets; Esc closes and returns focus (§5.5).
- [ ] "Load this lab" over unsaved editor work asks first; declining
      keeps the work (plan Review Focus 5).
- [ ] No console errors.

## 2. The editor's drag-to-draw keyboard path

§5.2: every function has a keyboard path — nothing is drag-only.

- [ ] Build a small tree (≥ 4 taxa) using only the keyboard: `N` new
      leaf, `J` join the two selected nodes, the arrow keys nudge the
      selected branch length, `Delete` detaches. The Newick text and
      the branch-length table show the same tree throughout — all three
      are views of one model (§5.1).
- [ ] Repeat the same build with pointer drags: the resulting Newick
      is identical.
- [ ] A drag that would create a unary node, a duplicate taxon name or
      a negative branch length is refused with a readable reason; undo
      restores the previous valid tree (§5.1).
- [ ] Every control has an accessible name; touch targets are ≥ 40×40
      px under `(pointer: coarse)`.

## 3. Save, import and share across machines

§5.4, success criterion 3 (§1).

- [ ] Build an exercise in the editor and save it: the downloaded file
      validates against `exercises/schema.json` and carries
      `schema_version` 3.
- [ ] Carry the file to another machine or a different browser:
      import loads the same tree, model, seed, length and prompts.
- [ ] Import accepts a `#x=` payload as well as a file — both go
      through the same validation and migration path.
- [ ] Share-link round trip: generate the link, open it in a private
      window — the exercise comes back identically.
- [ ] Build an exercise large enough that the encoded link exceeds the
      limit: the editor says the link is too long and offers the file
      instead — never a truncated URL (plan Review Focus 4).
- [ ] A file that fails validation is not downloaded; the editor shows
      the first failing field.

## 5. The new models on screen

§3.1, §5.3.

- [ ] The distance-correction menu offers `F84` and `K2P_PHYLIP`; the
      second is labelled "K2P (dnadist, κ = 2.0)". `K80` is unchanged
      and still offered alongside.
- [ ] The κ field appears only for `K2P_PHYLIP` and defaults to 2.0;

## Deviations from the plan

One line each; the full record is in `docs/decisions.md` under the
cited heading.

- An engine `add_leaf` op was added after Task 9 so spec §5.1's
  "creating a node is an engine operation" covers the keyboard `N`
  ("v1.4 Task 9a (follow-up): engine `add_leaf` edit op" — owner chose
  Option A on PR #96).
- Pack 1's `neighbor` NJ trees were committed in a separate
  fixture-only PR so the pack's tests could check trees against PHYLIP
  without tripping the CI fixture guard ("v1.4 Task 12a").
- Pack 3's oracle is a real PHYLIP `seqboot → dnadist → neighbor →
  consense` chain fixture — NeoPhylo's resampling cannot reproduce
  seqboot's draws — moved from `k80_10` to `jc12` by owner command on
  #104 ("v1.4 Task 12 pack 3a", "v1.4 Task 12 pack 3a-2").
- Fixture precision is now counted on raw PHYLIP printed output, and
  tests compare at split `dist_precision`/`tree_precision` rather than
  the single `precision` ("v1.4 follow-up P1", "v1.4 follow-up P2").
