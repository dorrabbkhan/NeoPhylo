# v1.4c release checkpoint — matrix input, lesson library and worksheets

Owner-run manual checklist before tagging `v1.4.2`, modeled on the v1.4b
release checkpoint (`docs/checkpoints/v1.4b-release.md`). Everything
automated is already green on the candidate — `./scripts/check.sh` plus
the full e2e browser matrix in CI — so this is the pass a machine can't
do alone: every oracle matrix through all three import routes on the
deploy, every paper worksheet and answer key looked at, the gate read,
the library at every width in both themes, the guide's links followed, a
matrix `.meg` carried into MEGA itself, and a printed page on paper.

(Tag name: `v1.4c` is the milestone name, not a valid release tag —
production deploys only on `v*.*.*` tags (`.github/workflows/ci.yml`).
`v1.4.2` is the proposed release tag; the owner confirms the name.
v1.4b shipped as `v1.4.1`. The agent never tags.)

How to run it: `docs/release-checkpoint.md`. `scripts/checkpoint/run.sh`
automates most items below against the deploy preview (its "Automation
map" says which), so the remaining manual pass is short:

    scripts/checkpoint/run.sh --pr <PR> --tag v1.4.2 --milestone v1.4c \
        --checklist docs/checkpoints/v1.4c-release.md

Use the deploy preview of the release-candidate commit, not a dev
server. Record findings inline under each item; anything blocking goes
back as a `fix/` branch before the tag. Spec references are to
`docs/superpowers/specs/2026-11-14-neophylo-v1.4c-matrix-and-library-design.md`.

Every number below comes from committed fixtures or committed test
output — `fixtures/inputs/matrix/` (the oracle inputs),
`fixtures/mega/matrix/` (MEGA-CC's trees on them), `fixtures/worked/`
(hand-verified textbook values), `web/src/state/__fixtures__/` (link
corpora) — never typed from memory. Section numbers (§) match the test
names in `scripts/checkpoint/browser/release.spec.ts`, which reports
each item it proves.

### The WebKit `d=` race found on main — fixed

CI run `44070866339` (main push for #159, job `e2e (webkit, 2)`)
failed `web/e2e/matrix.spec.ts` "leaving a matrix session restores the
alignment UI" twice — attempt and retry — at `expect(page.url()).
toContain("d=")` right after the tree became visible: the URL still
held the previous `lesson=nj-basics` link. The cause was real and
shared by all engines: the share URL was written by a passive
`useEffect` (`history.replaceState`) AFTER the render that painted the
tree (`web/src/views/App.tsx`), so there was a short window where the
page showed the new session under the old link. WebKit's pipeline hit
it reliably; the nightly on the same code passed, and the #160 push
run (`44086413192`) also passed — the window was timing-dependent, but
it was not a flake: a WebKit user who copied the address in that
window got a link without the matrix.

Fixed in this PR: the sync is now a `useLayoutEffect` in
`web/src/views/App.tsx`, so the URL is written before the new view
paints — `web/src/views/App.urlSync.test.tsx` pins the ordering by
reading `window.location` inside a commit-phase Profiler callback. The
e2e waits (`await expect(page).toHaveURL(/[?&]d=/)` in
`web/e2e/matrix.spec.ts` and `web/e2e/share.spec.ts`) stay as the
deterministic wait for the settled link; see `docs/decisions.md`.

## 16. Resolved rulings and known issues

- **`bootstrap: null` on a non-matrix exercise** (carried from Task 5,
      PR #151): the engine still loads an explicit JSON `null` for
      `bootstrap` as absent, while `exercises/schema.json` refuses it —
      a pre-existing serde null gap that older optional keys share
      (`sim.kappa: null`, …). Not fixed in v1.4c — deferred to v1.5
      (owner decision, 2026-11-17). Proposed v1.5 cleanup:
      presence-aware handling for all old optional keys plus
      ajv/engine agreement fixtures so the schema and the engine
      can't disagree again.
- **Lab-page print scale-down can push text under 12 px:** lab-page
      trees in print rely on the CSS `max-width` scale-down (not the
      round-3 `printFit` refit, which only answer-key finished trees
      use), so a very wide lab figure prints with its labels scaled
      below the 12 px floor. Deferred to v1.5 (owner decision,
      2026-11-17): apply the printable-width refit to lab print
      figures too.
- **§15 WebKit/Safari by hand stays unticked** (owner decision,
      2026-11-17): no Apple device is available; the automated WebKit
      pass in `release.spec.ts` covers the same items. The box above
      is for a real-device look and remains unchecked.
- **MEGA Adaptive Bootstrap** (resolved): v1.4c's `mega-bootstrap-100`
      is an NJ lab. The conductor's investigation found the Adaptive
      Bootstrap options in MEGA's ML lists, not NJ's, and the owner
      confirmed in the MEGA 12 GUI on 2026-11-17 (PR #160 status
      comment) that Neighbor-Joining → Test of Phylogeny offers no
      Adaptive option — the handout stays unchanged.
- **The WebKit `d=` window** — see §15; fixed in this PR (the URL sync
      is a layout effect written before paint, pinned by
      `App.urlSync.test.tsx`).
- **v1.4b carry-overs:** the globins UPGMA HBA three-way tie (either
      join is valid, the tie-aware parity test pins it — #128); no
      `JTT_MEGA` model anywhere (owner ruling on #117); MEGA GUI
      Newick-export hang seen on 2026-11-05 (a MEGA issue; MEGA-CC is
      the comparison path).
