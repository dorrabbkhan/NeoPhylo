# v1.4b release checkpoint — MEGA companion and data library

Owner-run manual checklist before tagging `v1.4.1`, modeled on the v1.4
release checkpoint (v1.4 plan Task 13). Everything automated is already
green — `RPARITY=1 FUZZ=1 ./scripts/check.sh` plus the full e2e browser
matrix in CI — so this is the pass a machine can't do: every MEGA handout
followed in real MEGA, each library dataset at every width in both
themes, a `.meg` file carried into MEGA itself, gap-treatment site counts
checked against MEGA's own, old links and exercise files, and a printed
handout.

(Tag name: `v1.4b` is the milestone name, not a valid release tag —
production deploys only on `v*.*.*` tags (`.github/workflows/ci.yml`).
`v1.4.1` is proposed here and in `CITATION.cff`; confirm before tagging.)

Use the deploy preview of the release-candidate commit, not a dev
server. Record findings inline under each item; anything blocking goes
back as a `fix/` branch before the tag. Spec references are to
`docs/superpowers/specs/2026-10-27-neophylo-v1.4b-mega-companion-design.md`.

The MEGA numbers below are taken from the committed MEGA-CC 12.1.4
fixtures (`fixtures/mega/library/`, `fixtures/mega/library/boot1000/`),
not from NeoPhylo's output — distances print at 8 decimals; branch
lengths at 16 (primate-mtdna) or 18 (globins, 16s-rrna) — each
fixture's `precision` block. Where an automated test already proves
an item against MEGA-CC, it is cited; the checkboxes are for the GUI
pass only MEGA's interface can do.

## 1. Handout `mega-jc69-vs-k2p` in real MEGA (GUI)

Follow the handout in the MEGA GUI on the owner's machine. The dataset
is `primate-mtdna` — the hominoid mitochondrial control region (D-loop),
7 taxa × 1,138 aligned sites, rebuilt from the same public Horai (1995)
accessions MEGA's `mtCDNA` example uses. It is **not** MEGA's example
file (~16.5 kb, over the 2,000-site cap): export the dataset from
NeoPhylo's Export menu as `.meg` and open that file in MEGA.

- [ ] `Distances → Compute pairwise distances`, then `Phylogeny →
      Construct/test NJ tree`, twice: Jukes-Cantor then Kimura
      2-parameter, every other option as the handout's settings table
      lists it.
- [ ] MEGA's matrix equals `JC69/pairwise` then `K80/pairwise` in
      `fixtures/mega/library/primate-mtdna.json` at its printed
      precision. Anchor cells: Homo_sapiens–Pan_troglodytes 0.15356507 /
      0.15713842; Pan_troglodytes–Pan_paniscus 0.10722178 / 0.10941981;
      Pongo_pygmaeus–Pongo_abelii 0.13624953 / 0.13887976;
      Hylobates_lar–Pongo_abelii 0.40990778 / 0.41651128.
- [ ] MEGA's NJ trees match `trees.nj/JC69/pairwise` and
      `trees.nj/K80/pairwise` in the same fixture (topology and branch
      lengths).
- Automated coverage: `parity_mega_library.rs`
      `library_distances_match_at_printed_precision` and
      `library_trees_match_topology_and_lengths` (MEGA-CC, both trees
      also replayed from MEGA's printed matrix).

## 2. Handout `mega-nj-vs-upgma` in real MEGA (GUI)

Dataset `globins` — 23 vertebrate globin sequences × 156 aligned amino
acids. Poisson distances under pairwise deletion, then an NJ tree and a
UPGMA tree on the same matrix.

- [ ] Follow the handout: `Distances → Compute pairwise distances`
      (Poisson model), `Phylogeny → Construct/test NJ tree`,
      `Phylogeny → Construct/test UPGMA tree`, all options per the
      settings table.
- [ ] MEGA's matrix equals `Poisson/pairwise` in
      `fixtures/mega/library/globins.json`. Anchor cells:
      Chimp_HBB–Human_HBB is exactly 0 (identical sequences);
      Human_HBA–Horse_HBA, Human_HBA–Cow_HBA and Horse_HBA–Cow_HBA are
      all exactly 0.12751332 — an exact three-way tie (17 differences of
      142 comparable sites). MEGA may resolve that tie to a different
      join than NeoPhylo's; either UPGMA tree is valid and the handout
      says so.
- [ ] MEGA's NJ tree matches `trees.nj/Poisson/pairwise`; the UPGMA tree
      matches `trees.upgma/Poisson/pairwise` up to the tie's join.
- Automated coverage: the same two parity tests plus
      `upgma_tie_resolutions_are_exactly` (MEGA's join is accepted only
      when it was one of the equally closest pairs — every other join
      stays exact).

## 3. Handout `mega-bootstrap-100` in real MEGA (GUI)

Dataset `16s-rrna` — 27 bacterial 16S rRNA sequences × 1,628 aligned
sites with real indels. NJ on Kimura 2-parameter distances with
`Test of Phylogeny: Bootstrap method`, `Bootstrap Replicates: 100`,
`Approach: Standard Bootstrap (slow)` — run under pairwise deletion,
then again under complete deletion.

- [ ] Follow the handout's two runs in MEGA with the exported `.meg`.
- [ ] Site counts: pairwise keeps all 1,628 columns (MEGA reports
      `No. of Sites = 1,628`); complete deletion keeps 1,199 (NeoPhylo
      shows "429 of 1,628 sites removed by complete deletion").
- [ ] The original NJ tree's splits match `bootstrap.nj/K80/pairwise`
      and `bootstrap.nj/K80/complete` in
      `fixtures/mega/library/16s-rrna.json`. Support counts will move
      within sampling noise — MEGA's bootstrap is unseeded; the
      handout's recorded values are the fixture's.
- Automated coverage: the boot1000 parity test (owner ruling on #126,
      option A) compares support within 5 percentage points of MEGA's
      1,000-replicate runs, with splits that only separate identical
      sequences excluded by a computed rule, not a hard-coded list.

## 4. Handout `mega-interpreting-support` in real MEGA (GUI)

- [ ] Run the chain at 100 then at 1,000 replicates on the exported

      Verify the sample opens from the Import data section and at least

## 6. Complete and partial deletion on 16S rRNA

      shows "429 of 1,628 sites removed by complete deletion" and marks

- [ ] Partial deletion, site coverage cutoff 95: MEGA keeps 1,294
